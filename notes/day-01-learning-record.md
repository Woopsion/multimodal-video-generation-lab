## 5. VLM、Diffusion、Video Generation 的区别和联系

### 5.1 VLM 是什么？

VLM 全称是 Vision-Language Model，视觉语言模型。

它主要解决：

> 让 AI 看懂图片/视频，并用语言回答。

典型输入输出：

```text
输入：图片/视频 + 问题
输出：文本回答
```

典型任务：

- 图片描述
- 图片问答
- OCR 理解
- 图表理解
- 截图理解
- 视频问答

典型结构：

```text
图片/视频
↓
视觉编码器
↓
视觉特征 / vision tokens
↓
投影层
↓
LLM 可接收的 embedding
↓
语言回答
```

核心问题：

> 如何把图片、视频等视觉信息转换成 LLM 能处理的 embedding/token，并让它和文本 token 在同一个语义空间里交互。

可以先记为：

```text
VLM = 视觉编码器 + 连接层/投影层 + LLM
```

### 5.2 Diffusion 是什么？

Diffusion 是扩散模型，是一类生成模型方法。

它主要解决：

> 从随机噪声中逐步生成图像或视频。

最基础的 Diffusion 可以这样理解：

```text
训练阶段：
真实图片
↓
逐步加噪
↓
变成带噪图片
↓
模型学习如何预测噪声

推理阶段：
随机噪声
↓
模型一步步去噪
↓
得到清晰图片
```

核心句子：

> Diffusion 的核心过程是：从随机噪声开始，经过多步去噪，最后得到目标图像或视频。

注意：

- 训练时会用真实图片加噪。
- 生成时通常从随机噪声开始。

### 5.3 Video Generation 是什么？

Video Generation 是视频生成。

它解决：

> 根据文本、图片或视频条件生成连续动态画面。

相比图像生成，视频生成多了时间维度。

图像生成主要关注：

```text
空间一致性：单张图内部是否合理
```

视频生成还要关注：

```text
时间一致性：帧与帧之间是否连贯
运动合理性：动作是否自然
主体一致性：人物或物体是否稳定
文本对齐：视频是否符合 prompt
```

### 5.4 三者一句话区分

```text
VLM：看懂视觉内容，然后说出来。
Diffusion：根据条件，从噪声生成视觉内容。
Video Generation：把视觉生成扩展到连续动态画面。
```

### 5.5 三者如何组合？

一个综合应用可以这样设计：

```text
用户上传图片
↓
VLM 理解图片内容
↓
LLM 改写成高质量 prompt
↓
Diffusion 生成新图片
↓
Video Diffusion 生成视频
```

这也是本学习路线最终想训练的系统能力：

```text
多模态理解 + 视觉生成 + 视频生成 + 工程应用
```

## 8. Latent Diffusion、Latent、张量与 VAE 学习笔记

### 8.1 Latent 是什么意思？

在 Latent Diffusion 中，`latent` 可以理解为：

> 潜在表示 / 隐空间表示 / 压缩后的特征表示

它不是原始图片，也不是人眼能直接看的图像，而是神经网络内部使用的一种压缩表示。

普通图片通常在像素空间 pixel space 中表示，例如：

```text
512 × 512 × 3
```

经过编码器压缩后，可能变成：

```text
64 × 64 × 4
```

这个较小的表示就叫：

```text
latent representation
latent code
latent variable
```

可以把 latent 理解为：

> 图片的“压缩草稿”或“模型能理解的特征地图”。

### 8.2 `512 × 512 × 3` 是什么意思？

一张 RGB 图片可以看成一个三维数组，也就是一个张量。

```text
512 × 512 × 3
```

通常表示：

```text
高度 × 宽度 × 通道数
```

也就是：

```text
512 行像素
512 列像素
每个像素有 3 个颜色通道
```

这里的 `3` 是 RGB：

```text
R = Red   红色
G = Green 绿色
B = Blue  蓝色
```

例如某个像素可能是：

```text
[R, G, B] = [255, 128, 0]
```

表示一个偏橙色的像素。

如果是普通 8-bit 图片，每个颜色通道一般取值：

```text
0 ~ 255
```

所以总像素数量是：

```text
512 × 512 = 262,144 个像素
```

总数字数量是：

```text
512 × 512 × 3 = 786,432 个数字
```

### 8.3 bit 位数越多，颜色越丰富吗？

通常是的。

如果每个颜色通道用 8 bit 表示：

```text
2^8 = 256
```

每个通道有 256 个等级：

```text
R: 0 ~ 255
G: 0 ~ 255
B: 0 ~ 255
```

总颜色数量为：

```text
256 × 256 × 256 = 16,777,216
```

也就是约 1677 万种颜色。

这通常叫：

```text
24-bit color = 8 bit × 3 通道
```

如果每个通道是 10 bit：

```text
2^10 = 1024
```

颜色层级更多，渐变更细腻。

如果每个通道是 12 bit：

```text
2^12 = 4096
```

颜色层级进一步增加。

总结：

> bit 位数越高，每个颜色通道的层级越细，颜色过渡越平滑。

但实际观感还取决于：

```text
显示器是否支持
图片内容
色域
动态范围
观看环境
```

bit depth 和 color gamut 的区别：

```text
bit depth = 颜色分得有多细
color gamut = 颜色范围有多广
```

### 8.4 像素数量越多，图片越清晰吗？

一般来说：

> 像素数量越多，理论上能表达的空间细节越多。

例如：

```text
512 × 512 = 262,144 像素
1920 × 1080 = 2,073,600 像素
3840 × 2160 = 8,294,400 像素
```

在同样拍摄质量、同样显示尺寸、同样观看距离下，分辨率越高通常越清晰。

但像素数量不完全等于清晰度。

清晰度还取决于：

```text
原始图像质量
对焦是否准确
是否运动模糊
镜头质量
压缩质量
显示尺寸
观看距离
PPI / DPI
```

如果一张低清图被强行放大成 4K，它虽然像素变多了，但真实细节并没有增加。

一句话总结：

> bit 位数决定颜色层次有多细，像素数量决定空间细节能有多少。

### 8.5 张量 Tensor 是什么？

简单说：

> 张量就是多维数组。

它是装数字的容器。

0 维张量：标量

```text
5
```

1 维张量：向量

```text
[1, 2, 3, 4]
```

2 维张量：矩阵

```text
[
  [1, 2, 3],
  [4, 5, 6]
]
```

3 维张量：图片

```text
512 × 512 × 3
```

4 维张量：一批图片

```text
16 × 512 × 512 × 3
```

在 PyTorch 中常见格式是：

```text
16 × 3 × 512 × 512
```

即：

```text
batch × channel × height × width
```

### 8.6 什么是 latent 张量？

原图：

```text
512 × 512 × 3
```

经过编码器后：

```text
64 × 64 × 4
```

这个：

```text
64 × 64 × 4
```

就是 latent 张量。

它不是 RGB 图片，而是模型内部的压缩特征表示。

原图中的 `3` 是：

```text
R、G、B
```

而 latent 中的 `4` 是：

```text
4 个模型学出来的特征通道
```

这 4 个通道不是：

```text
R、G、B、A
```

而是抽象特征。

### 8.7 为什么 `512 × 512 × 3` 会变成 `64 × 64 × 4`？

在 Stable Diffusion 常见设计中，VAE 编码器会把图像宽高各缩小 8 倍：

```text
512 / 8 = 64
512 / 8 = 64
```

所以空间尺寸从：

```text
512 × 512
```

变成：

```text
64 × 64
```

通道数从 3 变成 4，但这不是颜色通道，而是特征通道。

真正的数据量变化是：

原图：

```text
512 × 512 × 3 = 786,432 个数字
```

latent：

```text
64 × 64 × 4 = 16,384 个数字
```

压缩比例约为：

```text
786,432 / 16,384 = 48
```

也就是说，总数字数量减少了约 48 倍。

所以压缩主要来自：

```text
512 × 512 -> 64 × 64
```

而不是通道数变少。

事实上，通道数是从 3 变成了 4，略微变多了。

### 8.8 latent 里的 4 个特征通道如何理解？

原图的 RGB 表示：

```text
像素点 = [红, 绿, 蓝]
```

latent 中某个位置可以理解为：

```text
latent 点 = [特征1, 特征2, 特征3, 特征4]
```

但这些特征不是人工定义的，也不一定能用自然语言明确解释。

它们可能混合了：

```text
颜色趋势
亮暗变化
边缘方向
纹理结构
局部形状
语义倾向
```

重要的是：

> latent 中的 4 个值，是模型训练后自己学出来的内部描述。

### 8.9 latent 点对应原图中的什么？

因为宽高从 `512×512` 变成 `64×64`，缩小了 8 倍。

所以 latent 中的一个位置，不是对应原图中的一个像素，而是大致对应原图中的一小块区域。

粗略理解：

```text
latent 中 1 个位置 ≈ 原图中 8×8 或更大范围的一片区域
```

因此：

```text
latent 点 = [特征1, 特征2, 特征3, 特征4]
```

更像是在描述：

> 原图对应区域的综合视觉信息。

例如：

```text
这里大概是什么颜色趋势
有没有边缘
纹理是否复杂
亮度如何
局部形状如何
```

### 8.10 如何直观理解 latent？

#### latent 是模型能读懂的压缩语言

RGB 是给人和显示器看的：

```text
这个像素的红绿蓝是多少？
```

latent 是给神经网络看的：

```text
这个区域大概有什么结构、颜色、纹理和语义信息？
```

一句话：

> RGB 是颜色描述；latent 是特征描述。

#### latent 像图片的“压缩草稿”

原图是完整高清照片。

latent 像是一份压缩草稿：

```text
哪里是脸
哪里是头发
背景大概怎样
颜色趋势如何
边缘和纹理在哪里
```

Decoder 解码器可以根据这份草稿重新画回图片。

#### latent 像地图

现实世界包含无数细节：

```text
树叶
砖块
车辆
人物
光影
```

地图不会记录所有细节，但会记录重要结构：

```text
道路
河流
建筑
方向
区域关系
```

同样：

```text
latent 不是图片本身
```

但保留了生成和重建图片的重要信息。

#### latent 像描述一个人

像素方式描述一个人：

```text
第 1 个像素是什么颜色
第 2 个像素是什么颜色
……
```

latent 方式更像：

```text
脸朝左
头发深色
皮肤偏亮
背景较暗
衣服有纹理
轮廓大致这样
```

它不是逐像素记录，而是压缩后的视觉描述。

### 8.11 编码器 Encoder 如何实现压缩？

编码器通过神经网络把图片转换成 latent。

主要依靠：

```text
卷积 Convolution
下采样 Downsampling
特征通道 Feature Channels
训练学习
```

#### 卷积：提取局部特征

卷积层会学习检测：

```text
边缘
角点
纹理
颜色变化
局部形状
```

较浅层可能检测：

```text
横线
竖线
斜线
颜色块
```

较深层可能检测：

```text
眼睛
鼻子
轮廓
云朵
树叶
建筑结构
```

#### 下采样：缩小空间尺寸

编码器会逐步降低图片宽高：

```text
512 × 512
↓
256 × 256
↓
128 × 128
↓
64 × 64
```

这就是为什么 latent 的空间尺寸变小。

#### 特征通道：用抽象特征保存信息

原图通道是 RGB。

中间特征图的通道可能变成：

```text
64
128
256
```

最后压到 latent：

```text
64 × 64 × 4
```

这些通道不是颜色，而是模型学出来的特征。

### 8.12 为什么编码器能压缩图片？

因为图片有大量冗余。

例如一大片蓝天：

```text
很多相邻像素都差不多
```

没有必要逐个像素完整记录。

编码器可以用更少数字表示：

```text
这一片是蓝色渐变、较平滑、有一点云
```

再比如人脸有规律结构：

```text
眼睛
鼻子
嘴巴
轮廓
```

模型可以学习这些规律，用更少信息表达它。

所以编码器本质上是在学习：

> 什么信息重要，应该保留；什么细节可以压缩或省略。

### 8.13 VAE 是什么？

VAE 全称：

```text
Variational AutoEncoder
```

中文：

```text
变分自编码器
```

它由两部分组成：

```text
Encoder 编码器
Decoder 解码器
```

基本流程：

```text
输入图片 x
↓
Encoder
↓
latent z
↓
Decoder
↓
重建图片 x'
```

训练目标是：

```text
让 x' 尽量接近 x
```

也就是：

> 把图片压缩成 latent，再从 latent 尽量还原回图片。

### 8.14 AutoEncoder 自编码器是什么？

AutoEncoder 的作用是学习一种压缩表示。

流程：

```text
原始数据 -> 压缩编码 -> 还原数据
```

对于图片：

```text
图片 -> latent -> 图片
```

它有点像神经网络版的有损压缩器。

和 ZIP 不同：

```text
ZIP：尽量无损还原文件
AutoEncoder：保留主要视觉信息，允许有一定损失
```

### 8.15 VAE 比普通 AutoEncoder 多了什么？

普通 AutoEncoder：

```text
Encoder 直接输出一个 latent z
```

VAE：

```text
Encoder 输出一个分布
```

更具体地，VAE Encoder 通常输出：

```text
均值 μ
方差 σ
```

然后从这个分布中采样得到 latent：

```text
z = μ + σ × noise
```

直观理解：

> VAE 不是把图片压成一个固定点，而是压成一个概率分布附近的 latent。

这样可以让 latent 空间更连续、更规则，便于生成模型使用。

### 8.16 VAE 在 Stable Diffusion 中的作用

Stable Diffusion 不直接在原图 RGB 像素空间中生成，而是在 latent 空间中生成。

编码过程：

```text
图片
↓
VAE Encoder
↓
latent
```

例如：

```text
512 × 512 × 3
↓
64 × 64 × 4
```

生成过程：

```text
随机噪声 latent
↓
U-Net 去噪
↓
生成后的 latent
↓
VAE Decoder
↓
最终图片
```

所以 VAE 的作用可以理解为：

> 在图片空间和 latent 空间之间做转换。

```text
图片空间 <-> latent 空间
```

### 8.17 Latent Diffusion 为什么要在 latent 空间生成？

因为直接在像素空间生成计算量太大。

像素空间：

```text
512 × 512 × 3 = 786,432 个数字
```

latent 空间：

```text
64 × 64 × 4 = 16,384 个数字
```

latent 空间小很多。

优点：

```text
速度更快
显存占用更低
训练成本更低
仍能保留主要视觉信息
```

所以 Latent Diffusion 的核心思想是：

> 不直接操作每个像素，而是先把图片压缩成 latent，在 latent 空间里做扩散生成，最后再解码成图片。

### 8.18 最终核心总结

关于 RGB：

```text
512 × 512 × 3
```

表示一张 RGB 图片：

```text
512 高
512 宽
3 个颜色通道：R、G、B
```

RGB 是人类和显示器容易理解的颜色表示。

关于 latent：

```text
64 × 64 × 4
```

表示压缩后的 latent 特征图：

```text
64 高
64 宽
4 个模型学出来的特征通道
```

这里的 `4` 不是 RGB，也不是 RGBA，而是抽象特征。

关于张量：

> 张量就是多维数组。

图片、latent、神经网络中间特征，通常都可以表示为张量。

关于编码器：

```text
RGB 图片 -> latent 特征
```

Encoder 通过卷积、下采样和训练学习实现压缩。

关于解码器：

```text
latent 特征 -> RGB 图片
```

Decoder 根据 latent 中的信息还原图像。

关于 VAE：

```text
VAE = Encoder + Decoder
```

在 Stable Diffusion 中负责：

```text
图片空间 <-> latent 空间
```

一句话总括：

> RGB 图片是“每个像素是什么颜色”；latent 是“模型学出来的压缩视觉描述”；VAE 负责在这两者之间转换；Latent Diffusion 则在更小、更高效的 latent 空间中完成图像生成。
