2. CLIP 解决什么问题

先从一个很具体的问题开始：给你一张图片和三句话，机器怎么判断哪句话最像这张图片？

图片

一只黑色小狗站在草地上。

候选文本

  1. 一只小狗在草地上。
  2. 一辆红色汽车在路边。
  3. 一碗面条放在桌上。

人类可以直接看语义。但模型不能直接把“像素”和“中文句子”拿来比较，因为它们的数据形态完全不同：

对象 原始形态 为什么不能直接比较
图片 [C, H, W] 像素张量 数值表示颜色和空间位置。
文本 token id 序列 数值表示词表里的离散编号。

CLIP 的核心想法：不要直接比较原始图片和原始文字。先分别编码成同维度向量，再比较这两个向量是否接近。

这里的“对齐”不是把文字贴到图片上，而是让“图片向量”和“文本向量”在同一个坐标系里能互相比较。

3. 双塔结构

CLIP 的结构通常被称为 dual encoder，也就是双编码器或双塔结构。

image -> image_encoder -> image_embedding
text -> text_encoder -> text_embedding

这里的 image_embedding 和 text_embedding 必须有相同维度。比如都变成 D = 512 维，模型才能做点积或余弦相似度。

模块 输入 输出 你可以如何类比
Image Encoder 图片像素或 patch token image_embedding [D] Day8 的 ViT image encoder。
Text Encoder 文本 token id text_embedding [D] Day6 的 Transformer 文本编码流程。

注意：CLIP 不是让图片直接进入 LLM。CLIP 的重点是训练两个编码器，让图像向量和文本向量在同一个空间里可以比较。

4. 编码器 shape：从一批输入到一批向量

Step 02 的关键不是背结构名，而是看懂两条路径的 shape 怎么从“原始输入”一步步变成“同维度向量”。

先定义符号：B 表示 batch size，也就是一次送进模型的样本数量；C 表示图片通道数，RGB 图片通常是 3；H 和 W 表示图片高度和宽度；N 表示 patch 数量；L 表示文本 token 数量；D 表示 CLIP 最后用来比较图文的共享向量维度。

4.1 图片塔：image encoder 的完整形状流

图片进入 CLIP 时，通常不是直接变成一个向量。它会先经过 Day8 学过的 patch embedding，把一张图片变成一串 patch token，然后用 ViT 或其他视觉编码器处理。 

images.shape = [B, C, H, W]

patch_embeddings.shape = [B, N, d_image_hidden]
加上 class token 后：
image_tokens.shape = [B, 1 + N, d_image_hidden]

image_encoder(image_tokens)
-> image_hidden_states.shape = [B, 1 + N, d_image_hidden]

取 class token 或做 pooling：
image_pooled.shape = [B, d_image_hidden]

再过 image projection：
image_embeddings.shape = [B, D]

这里要分清楚两个层级：patch_embeddings 或 image_hidden_states 里的一行 token 可以表示某个 patch；但 image_embeddings 已经是经过 class token / pooling 汇总、再经过 projection 后得到的整张图片向量。也就是说，image_embeddings[b] 表示第 b 张图片的全局语义向量，不是第 b 个 patch 的向量。

步骤 shape 含义
原始图片 [B, C, H, W] 一批图片，每张图片还是像素张量。
Patch Embedding [B, N, d_image_hidden] 每张图片被切成 N 个 patch，每个 patch 变成一个向量。
视觉编码器输出 [B, 1 + N, d_image_hidden] 每个 patch token 都被 Transformer 更新过，class token 也汇总了图片信息。
图片汇总向量 [B, d_image_hidden] 每张图片最终先取出一个代表整张图的向量。
CLIP 图片向量 [B, D] 投影到共享维度 D，准备用来和文本向量比较。

类比 Day8：Day8 的 cls_output.shape = [B, embed_dim] 就是“一张图片一个汇总向量”的雏形。CLIP 里还会再接一个 projection，把它变成用于图文对齐的 [B, D]。

4.2 Class Token 和 Mean Pooling 都能得到整图向量

你的理解是对的：ViT 里图片先被切成 patch，再变成 patch token。加入 class token 后，序列通常是： 

patch_tokens.shape = [B, N, D]
cls_token.shape    = [B, 1, D]

vit_input.shape    = [B, 1 + N, D]
encoder_output.shape = [B, 1 + N, D]

送入 Transformer Encoder 后，所有 token 会通过 self-attention 多层混合信息。此时 class token 不再只是一个随机的占位向量；它经过多层注意力后，可以吸收 patch token 的信息。更准确地说：如果训练目标把 loss 接在 class token 后面，模型就会被迫学会让 class token 承担“整张图代表”的职责。

方式 A：取 class token

encoder_output.shape = [B, 1 + N, D]

cls_output = encoder_output[:, 0, :]
cls_output.shape = [B, D]

第 0 个 token 是 class token。训练后它会倾向于聚合整张图的信息，所以可以作为整图向量。

方式 B：对 patch token 做平均

patch_outputs = encoder_output[:, 1:, :]
patch_outputs.shape = [B, N, D]

mean_output = patch_outputs.mean(dim=1)
mean_output.shape = [B, D]

dim=1 表示沿着 patch/token 维度求平均。它不是把所有数字加成一个数，而是每个特征维度单独对所有 patch 求平均。

用公式写 mean pooling：

mean_output[b, k] = (patch_output[b, 0, k] + ... + patch_output[b, N - 1, k]) / N

这里 b 表示第几张图片，k 表示第几个特征维度，N 表示 patch 数量。也就是说，平均的是“所有 patch 在同一个特征维度上的值”，最后仍然保留 D 个维度，得到一个整图向量。

汇总方式 怎么得到 [B, D] 直观理解 注意点
Class Token encoder_output[:, 0, :] 让一个专门的可学习 token 通过注意力收集全图信息。 它能不能代表整图，依赖训练目标是否持续要求它这么做。
Mean Pooling encoder_output[:, 1:, :].mean(dim=1) 把所有 patch token 的输出按维度平均，得到全图平均表示。 每个 patch 权重相同；但 patch token 已经经过 self-attention，所以里面也可能含有全局上下文。

关键结论：class token 和 mean pooling 都是在把 [B, 1 + N, D] 或 [B, N, D] 压成 [B, D]。压出来的这个 [B, D] 才是后面 CLIP 相似度矩阵里的 image_embeddings 来源。

4.3 文本塔：text encoder 的完整形状流

文本进入 CLIP 时，先经过 tokenizer 变成 token id。注意：token id 本身不是语义向量，它只是词表里的编号；真正的向量要通过 token embedding 查表得到。 

texts = ["一只小狗在草地上", "一辆红色汽车在路边"]

input_ids.shape = [B, L]
attention_mask.shape = [B, L]

token_vectors.shape = [B, L, d_text_hidden]

text_encoder(token_vectors)
-> text_hidden_states.shape = [B, L, d_text_hidden]

取 EOS token / CLS token / pooling：
text_pooled.shape = [B, d_text_hidden]

再过 text projection：
text_embeddings.shape = [B, D]
步骤 shape 含义
Token IDs [B, L] 一批文本，每句话被 tokenizer 切成 L 个 token id。
Token Embedding [B, L, d_text_hidden] 每个 token id 查表得到一个向量。
文本编码器输出 [B, L, d_text_hidden] 每个 token 的向量都融合了这句话里的上下文信息。
文本汇总向量 [B, d_text_hidden] 每句话最终先取出一个代表整句文本的向量。
CLIP 文本向量 [B, D] 投影到共享维度 D，准备用来和图片向量比较。

4.4 为什么最后都必须是 [B, D]

因为 CLIP 最后要比较图片向量和文本向量。如果图片向量是 [B, 512]，文本向量是 [B, 768]，这两个向量就没法直接做点积。它们的坐标数量不同，相当于一个点在 512 维坐标系，一个点在 768 维坐标系。

所以 CLIP 会给两边各加一个投影层：

image_embeddings = image_pooled @ W_image
text_embeddings = text_pooled @ W_text

这里的 W_image 和 W_text 都是可学习参数矩阵。它们的作用不是“随便改形状”，而是把两种模态都翻译到同一个比较标准里。

本阶段最重要的一句话：CLIP 的两个 encoder 可以用不同内部结构、不同 hidden size，但最终必须输出同一个共享维度 D 的向量，因为后面要把图片向量和文本向量放在同一张相似度表里比较。

5. 相似度矩阵：每张图和每句话两两打分

Step 03 的核心是看懂这行代码背后的含义：logits = image_embeddings @ text_embeddings.T。

先定义符号：I 表示图片向量矩阵，shape 是 [B, D]；T 表示文本向量矩阵，shape 也是 [B, D]。这里的 B 是一批图文对的数量，D 是每个向量的维度。

5.1 为什么是 [B, D] @ [D, B] -> [B, B]

image_embeddings 里每一行是一张图片的整图向量，不是 patch 向量。text_embeddings 里每一行是一条文本的整句向量，不是某个 token 的向量。为了让每张图都和每条文本比较，我们需要把文本矩阵转置。

张量 shape 每一行 / 每个位置表示什么
patch_embeddings [B, N, d_image_hidden] 第 b 张图里的第 n 个 patch 向量。
image_hidden_states [B, 1 + N, d_image_hidden] 经过视觉 encoder 更新后的 class token 和 patch token 向量。
image_pooled [B, d_image_hidden] 每张图汇总后的全局图片向量，通常来自 class token 或 pooling。
image_embeddings [B, D] 每张图投影到 CLIP 共享空间后的整图向量，用来和文本向量做相似度。 
image_embeddings.shape = [B, D]
text_embeddings.shape  = [B, D]

text_embeddings.T.shape = [D, B]

logits = image_embeddings @ text_embeddings.T
logits.shape = [B, B]

这个 [B, B] 矩阵不是新的一批向量，而是一张分数表。第 i 行表示“第 i 张图片分别和所有文本的匹配分数”；第 j 列表示“所有图片分别和第 j 条文本的匹配分数”。

text 0 text 1 text 2
image 0 logits[0,0] logits[0,1] logits[0,2]
image 1 logits[1,0] logits[1,1] logits[1,2]
image 2 logits[2,0] logits[2,1] logits[2,2]

5.2 每一个格子具体怎么算

相似度矩阵里的一个格子，可以写成：

scorei,j = ∑k=0D-1 Ii,k · Tj,k

这句话拆开看：

  • scorei,j：第 i 张图片和第 j 条文本的相似度分数。
  • Ii,k：第 i 张图片向量的第 k 个坐标值。
  • Tj,k：第 j 条文本向量的第 k 个坐标值。
  • k：向量维度下标，从 0 到 D - 1。
  • ∑k=0D-1：让 k 从 0 一直取到 D - 1，把所有维度上的乘积加起来，这就是点积。

用一个非常小的例子看。假设 D = 2，也就是每张图片和每条文本都只用 2 个数字表示： 

image 0 = [0.8, 0.6]
text 0  = [0.7, 0.7]
text 1  = [0.1, 0.9]

score[0, 0] = 0.8 * 0.7 + 0.6 * 0.7 = 0.98
score[0, 1] = 0.8 * 0.1 + 0.6 * 0.9 = 0.62

在这个例子里，image 0 和 text 0 的分数更高，所以模型会认为 text 0 更匹配这张图片。

5.3 为什么对角线通常是正确答案

训练 CLIP 时，一个 batch 通常会放 B 对图文。第 0 张图配第 0 条文本，第 1 张图配第 1 条文本，以此类推。 

image 0 <-> text 0
image 1 <-> text 1
image 2 <-> text 2

所以在 [B, B] 的相似度矩阵里，对角线位置 logits[0,0]、logits[1,1]、logits[2,2] 是正确图文对。非对角线位置，例如 logits[0,2]，表示“第 0 张图”和“第 2 条文本”的错误组合。

5.4 为什么这里也叫 logits

在 Day3 里，logits 是“还没有 softmax 的原始类别分数”。在 CLIP 里也类似：相似度矩阵里的每个值也是原始分数，还不是概率。

真实 CLIP 里常见写法会多乘一个可学习的缩放系数：

logits = exp(logit_scale) * image_embeddings @ text_embeddings.T
  • logit_scale：一个可学习标量，也就是一个数字参数。
  • exp(logit_scale)：保证缩放系数是正数。exp(x) 表示 e^x。
  • 它的作用是调整分数的“尖锐程度”：分数差距更明显时，softmax 后概率也会更集中。

本阶段先别急着推 loss：现在只需要知道 [B, B] 的每个格子都是一个图文匹配分数；对角线是正确配对；下一阶段的 contrastive loss 会围绕这张分数表做 CrossEntropyLoss。

6. Contrastive Loss：把对角线推高，非对角线压低

Step 04 的关键是把 CLIP loss 看成两个方向的分类问题：图片找正确文本，文本找正确图片。

先定义符号：S 表示相似度矩阵，也就是上一节的 logits，shape 是 [B, B]。Si,j 表示第 i 张图片和第 j 条文本的匹配分数。B 是一个 batch 中图文对数量。

6.1 什么叫 contrastive

Contrastive 的意思是“对比式”。CLIP 不只是告诉模型“这张图对应这句话”，还会在同一个 batch 里拿其他图片和其他文本当反例。

概念 在 CLIP batch 里的含义
正样本 positive pair 原本配对的图文，例如 image 1 和 text 1。
负样本 negative pair 同一个 batch 里的错误组合，例如 image 1 和 text 0、text 2。
对比学习 让正样本分数更高，让负样本分数更低。

6.2 图片找文本：把每一行当作一次分类

先看第一种方向：image-to-text，也就是“给定一张图片，从 B 条文本里选出正确文本”。 

S.shape = [B, B]

row 0 = image 0 对所有 texts 的分数
row 1 = image 1 对所有 texts 的分数
row 2 = image 2 对所有 texts 的分数

如果 batch 是按图文对排列的，那么第 i 张图片的正确文本就是第 i 条文本。因此标签是：

labels = [0, 1, 2, ..., B - 1]

这和 Day3 的 MNIST 分类很像。MNIST 是“图片 -> 10 个数字类别”；这里是“图片 -> B 条候选文本类别”。 

# PyTorch 视角：
loss_i2t = CrossEntropyLoss(S, labels)

CrossEntropyLoss(S, labels) 的意思是：把 S 的每一行当成一组 logits。每一行里，正确类别的位置就是对角线位置。

6.3 文本找图片：再把每一列当作一次分类

CLIP 不只训练“图片找文本”，还训练“文本找图片”。也就是给定一条文本，从 B 张图片里选出正确图片。

原矩阵 S 的列表示“所有图片对某条文本的分数”。为了继续使用 CrossEntropyLoss 的“每一行是一个样本”习惯，我们把矩阵转置： 

S.T.shape = [B, B]

row 0 = text 0 对所有 images 的分数
row 1 = text 1 对所有 images 的分数
row 2 = text 2 对所有 images 的分数

loss_t2i = CrossEntropyLoss(S.T, labels)

最终 CLIP loss 通常取两个方向的平均：

loss = (loss_i2t + loss_t2i) / 2

6.4 单行 CrossEntropyLoss 到底怎么算

假设只看 image 0 这一行。它对 3 条文本的分数是： 

S[0] = [4.0, 1.0, 0.5]
正确文本是 text 0，所以 label = 0

对这一行做 softmax：

pj = exp(S0,j) / ∑m=0B-1 exp(S0,m)
  • pj：模型认为第 j 条文本匹配 image 0 的概率。
  • exp(x)：表示 e^x，保证每个分数变成正数。
  • ∑m=0B-1：让 m 遍历这一行所有候选文本，把所有 exp 值加起来，作为归一化分母。

因为正确文本是 text 0，所以这一行的 loss 是：

loss_row0 = -log(p[0])

如果 p[0] 很接近 1，说明正确文本概率高，-log(p[0]) 很小；如果 p[0] 很小，说明模型把错误文本看得更像，loss 就会很大。

关键澄清：单行 loss 最后确实写成 -log(p[正确类别])，但这不表示错误类别没有参与。因为 p[正确类别] 是 softmax 之后的概率，而 softmax 的分母包含这一行所有类别的分数。

还是以正确类别是 text 0 为例。令这一行 logits 是：

z = [z0, z1, z2]

那么正确类别概率不是只看 z0，而是：

p0 = exp(z0) / (exp(z0) + exp(z1) + exp(z2))

所以这一行 loss 可以写成：

L = -log(p0) = -z0 + log(exp(z0) + exp(z1) + exp(z2))

你看，z1 和 z2 明确出现在第二项里。如果错误类别分数变大，分母会变大，p0 会变小，-log(p0) 就会变大。

6.4.1 L = -∑ yj log(pj) 是怎么来的

这个公式不是从 softmax 里“自动长出来”的，而是我们为分类问题选择的训练目标：让模型给真实类别尽可能高的概率。更正式一点，它来自最大似然估计，也就是 maximize likelihood。

先不用 one-hot，先看最朴素的一句话：如果正确答案是 text 0，模型给正确答案的概率是 p[0]。我们希望 p[0] 越大越好。

目标：让 p[正确类别] 尽量接近 1

训练时通常不直接最大化 p[正确类别]，而是最小化它的负对数：

Loss = -log(p[正确类别])

为什么要加 log？有三个现实原因：

  • log 是单调递增函数，所以让 p 变大，等价于让 log(p) 变大。
  • 加负号以后，最大化 log(p) 就变成最小化 -log(p)，正好符合训练里“最小化 loss”的习惯。
  • -log(p) 对“自信但错”的惩罚很大：如果正确概率 p=0.9，loss 很小；如果 p=0.01，loss 会很大。
正确类别概率 p -log(p) 直观含义
0.9 约 0.105 模型很相信正确答案，惩罚很小。
0.5 约 0.693 模型有点犹豫，惩罚中等。
0.01 约 4.605 模型几乎不相信正确答案，惩罚很大。

现在引入 one-hot。假设有 3 个候选文本，正确答案是 text 0：

y = [1, 0, 0]

其中 yj 表示第 j 个位置是不是正确答案：正确位置是 1，错误位置是 0。

如果模型输出概率：

p = [p0, p1, p2]

那么这个式子：

∑j=02 yj log(pj)

实际上只会留下正确类别那一项。因为错误位置的 yj 都是 0：

y0log(p0) + y1log(p1) + y2log(p2)
= 1 · log(p0) + 0 · log(p1) + 0 · log(p2)
= log(p0)

加上负号，就回到了刚才的负对数似然：

L = -∑j=0B-1 yj log(pj)
Loss = -log(p[正确类别])

一句话：-∑ yjlog(pj) 只是 -log(p[正确类别]) 的 one-hot 写法。one-hot 像一个选择器，只把正确类别那一项选出来。

情况 A：正确分数最高

S[0] = [4.0, 1.0, 0.5]
softmax 后：
p ≈ [0.925, 0.046, 0.028]
loss = -log(0.925) ≈ 0.078

loss 很小，说明当前判断比较好。

情况 B：错误分数最高

S[0] = [1.0, 4.0, 0.5]
softmax 后：
p ≈ [0.046, 0.925, 0.028]
loss = -log(0.046) ≈ 3.08

loss 很大，说明模型把错误文本排到前面了。

6.5 它如何真正推高对角线、压低非对角线

你在 Day3 已经问过 CrossEntropyLoss 的梯度。这里同样可以用那条关键公式：

∂L / ∂Si,j = pi,j - yi,j

每个符号的含义是：

  • Si,j：相似度矩阵里的一个 logit，表示第 i 张图和第 j 条文本的分数。
  • pi,j：对第 i 行 softmax 后，第 j 条文本的概率。
  • yi,j：真实标签的 one-hot 值。正确位置是 1，错误位置是 0。
  • ∂L / ∂Si,j：loss 传到这个中间分数上的梯度信号。它不是说 optimizer 会直接更新 Si,j，而是告诉反向传播：产生这个分数的上游变量和参数应该收到什么方向的影响。

对角线位置是正确答案，所以 yi,i = 1。如果当前模型还没完全判断对，通常 pi,i < 1，于是：

∂L / ∂Si,i = pi,i - 1

这个值是负数。严格说，Si,i 本身不是参数，不会被 optimizer 直接更新；这个负梯度会继续传回 image_embeddings、text_embeddings 以及更上游的模型参数。参数更新之后，下一次 forward 重新算出来的 Si,i 会倾向于变大。

非对角线位置是错误答案，所以 yi,j = 0。于是：

∂L / ∂Si,j = pi,j

这个值是正数。同样，Si,j 不是被直接修改；这个正梯度会通过链式法则影响产生它的上游参数。参数更新之后，下一次 forward 重新算出来的非对角线分数 Si,j 会倾向于变小。

6.5.1 重新推导：为什么梯度等于 p - y

先只看一行，也就是“某一张图片在所有文本里选正确文本”。假设当前看第 i 张图片，这一行有 B 个候选文本。为了让推导更干净，先把这一行单独记成一组 logits：

zj = Si,j,   j = 0, 1, ..., B - 1

这里 zj 表示第 j 条文本的原始分数。它只是 S 第 i 行里的一个元素。

softmax 把这组 logits 变成概率：

A = ∑r=0B-1 exp(zr)
pj = exp(zj) / A
  • A：softmax 的分母，也就是这一行所有 exp(zr) 的总和。
  • r：求和下标，从 0 到 B - 1 遍历所有候选文本。
  • pj：模型认为第 j 条文本匹配当前图片的概率。
  • B：候选文本数量，也就是当前 batch 里的图文对数量。

CrossEntropyLoss 对 one-hot 标签的标准写法是：

L = -∑j=0B-1 yj log(pj)

L 是当前这一行的 loss。yj 是 one-hot 标签：正确位置是 1，错误位置是 0。比如正确文本是第 2 条，且 B = 3，那么 y = [0, 0, 1]。

现在把 pj 代入 log(pj)：

log(pj) = log(exp(zj) / A)
log(pj) = log(exp(zj)) - log(A)
log(pj) = zj - log(A)

这里用到了两个基础性质：log(a / b) = log(a) - log(b)；并且 log 是自然对数，所以 log(exp(zj)) = zj。

代回 loss：

L = -∑j=0B-1 yj(zj - log(A))
L = -∑j=0B-1 yjzj + ∑j=0B-1 yjlog(A)

注意 A 是这一整行 logits 的 softmax 分母。对固定的一行来说，log(A) 不带下标 j，所以它在第二个求和里是同一个值。

one-hot 标签里只有一个位置是 1，其他位置是 0，因此：

∑j=0B-1 yj = 1
∑j=0B-1 yjlog(A) = log(A)

所以 loss 可以简化成：

L = -∑j=0B-1 yjzj + log(A)

现在对某个分数 zk 求偏导。k 表示我们正在观察的那个候选文本位置。

第一项的偏导：

∂ / ∂zk (-∑j=0B-1 yjzj) = -yk

原因是：这个求和里只有 j = k 的那一项包含 zk，也就是 -ykzk；其他项和 zk 无关，偏导是 0。

第二项的偏导：

∂ / ∂zk log(A) = (1 / A) · ∂A / ∂zk

这是链式求导。可以把 log(A) 看成两层函数：

外层：f(A) = log(A)
内层：A = A(z0, z1, ..., zB-1)

我们要求的是 log(A) 对 zk 的偏导，所以要先问：A 变一点时 log(A) 怎么变？再问：zk 变一点时 A 怎么变？

∂log(A) / ∂zk = (∂log(A) / ∂A) · (∂A / ∂zk)

第一部分是自然对数的基本导数：

∂log(A) / ∂A = 1 / A

所以剩下只需要算 ∂A / ∂zk。而 A 的定义是：

A = ∑r=0B-1 exp(zr)

为了不让求和符号太飘，假设 B = 3，那么：

A = exp(z0) + exp(z1) + exp(z2)

如果现在对 z1 求偏导，意思是：只让 z1 变化，暂时把 z0 和 z2 当成常量。

∂A / ∂z1 = ∂exp(z0)/∂z1 + ∂exp(z1)/∂z1 + ∂exp(z2)/∂z1

第一项里没有 z1，所以导数是 0；第三项也没有 z1，导数也是 0。只有中间这一项真的含有 z1：

∂A / ∂z1 = 0 + exp(z1) + 0 = exp(z1)

换成任意位置 k，同理只有 exp(zk) 这一项会随着 zk 变化：

∂A / ∂zk = exp(zk)

把两层乘起来：

∂ / ∂zk log(A) = exp(zk) / A

而 softmax 定义里：

pk = exp(zk) / A

因此：

∂ / ∂zk log(A) = pk

两项合起来：

∂L / ∂zk = -yk + pk
∂L / ∂zk = pk - yk

最后把 zk 换回 CLIP 的矩阵元素：zk = Si,k。

∂L / ∂Si,k = pi,k - yi,k

把下标 k 换成通用位置 j，就得到：

∂L / ∂Si,j = pi,j - yi,j

直觉版：如果某个位置是正确答案，y=1，梯度是 p-1，通常是负数；如果某个位置是错误答案，y=0，梯度是 p，是正数。这不是直接改 logits，而是把“希望下次这个 logit 更高或更低”的信号传给上游参数。

6.5.2 重要修正：Si,j 不是参数，谁才会被更新？

你指出的问题非常关键：Si,j 是一次 forward 过程中临时算出来的中间结果，不是可学习参数。它就像 Day3 里的 logits 一样，本身不会被 optimizer 保存，也不会在 optimizer.step() 时被直接改掉。

在 CLIP 里，单个分数来自点积：

Si,j = scale · image_embeddingi · text_embeddingj

其中：

  • scale：通常来自 exp(logit_scale)，是可学习缩放系数。
  • image_embedding[i]：第 i 张图片经过 image encoder 和 image projection 算出来的整图向量。
  • text_embedding[j]：第 j 条文本经过 text encoder 和 text projection 算出来的整句向量。

所以 ∂L / ∂Si,j 的作用，是继续通过链式法则传给这些上游量：

∂L / ∂image_embeddingi 包含 (∂L / ∂Si,j) · text_embeddingj
∂L / ∂text_embeddingj 包含 (∂L / ∂Si,j) · image_embeddingi

如果把上游继续展开：

image_embedding[i] = image_projection(image_encoder(image_i))
text_embedding[j] = text_projection(text_encoder(text_j))

那么梯度会继续传到：

  1. image projection 的权重参数。
  2. text projection 的权重参数。
  3. image encoder 里的 ViT/CNN 参数。
  4. text encoder 里的 Transformer/token embedding 参数。
  5. 如果启用可学习缩放，logit_scale 也会收到梯度。

因此更严谨的说法是：∂L / ∂Si,j 不是“直接调整这个分数”，而是“告诉产生这个分数的上游参数，怎样更新后能让下一次 forward 的这个分数朝目标方向变化”。

严谨版结论：S 是中间计算结果；dLoss/dS 是反向传播经过这个中间节点时的梯度；真正被 optimizer.step() 更新的是模型参数，不是 S 这张临时分数表。

6.6 梯度最终影响哪些参数

Si,j 不是凭空来的，它来自图片向量和文本向量的点积：

Si,j = image_embeddingsi · text_embeddingsj

所以 loss 对 S 的梯度，会继续通过链式法则传回：

  1. image_embeddings 和 text_embeddings。
  2. W_image 和 W_text 两个投影矩阵。
  3. Image Encoder 里的 ViT/CNN 参数。
  4. Text Encoder 里的 Transformer/token embedding 参数。

这就是“图文向量被训练到同一个空间”的底层原因：不是人为手动摆放向量，而是 loss 通过梯度不断修改两个 encoder 和 projection 的参数。

本阶段最重要的一句话：CLIP 的 contrastive loss 本质上是对同一张 [B, B] 相似度矩阵做两次 CrossEntropyLoss：一次让图片找对文本，一次让文本找对图片。

7.2.1 F.normalize(..., dim=1) 不是“减均值除标准差”

demo 里有两行代码： 

image_embeddings = F.normalize(image_raw, dim=1)
text_embeddings = F.normalize(text_raw, dim=1)

这里的 normalize 是 L2 归一化，不是统计学里常说的标准化。它不会计算这一行的均值，也不会计算这一行的标准差。

对 image_raw.shape = [B, D] 来说，dim=1 表示沿着每一行的 D 个维度计算向量长度。也就是：每一张图片的整图向量单独归一化，每一条文本的整句向量也单独归一化。

normb = sqrt(xb,02 + xb,12 + ... + xb,D-12)
normalized_xb,k = xb,k / normb
  • b：第几行，也就是第几张图片或第几条文本。
  • k：这一行向量里的第几个维度。
  • normb：第 b 行向量的 L2 长度。

一个具体例子： 

x = [3, 4]
L2 norm = sqrt(3^2 + 4^2) = 5
F.normalize(x) = [3/5, 4/5] = [0.6, 0.8]

归一化后的向量长度变成 1：

sqrt(0.62 + 0.82) = 1
操作 公式 目的
L2 归一化 x / ||x||₂ 只改变向量长度，让每个向量长度变成 1，方向基本保持不变。
均值/标准差标准化 (x - mean) / std 把一组数平移并缩放，让它均值约为 0、标准差约为 1。

为什么 CLIP 这里常做 L2 归一化：后面要用点积比较图文向量。如果两个向量都被归一化到长度为 1，那么点积主要反映方向是否接近，也就是 cosine similarity。这样模型比较的是“语义方向接近不接近”，而不是谁的向量长度更大。

变量 本 demo 里的 shape 含义
image_embeddings [3, 4] 3 张图片的整图向量，每张图片 4 个维度。
text_embeddings [3, 4] 3 条文本的整句向量，每条文本 4 个维度。
logits [3, 3] 每张图片和每条文本两两比较后的原始分数表。
labels [3] [0, 1, 2]，表示对角线是正确匹配。
loss 标量 图片找文本 loss 和文本找图片 loss 的平均值。

7.2.2 脚本里的 Step 05 和 Step 06 到底在算什么

这两个步骤最容易混，因为它们用的是同一张 logits 表，只是读表方向不同。先固定一个事实： 

logits.shape = [B, B]

行：image 0, image 1, image 2
列：text 0,  text 1,  text 2

所以 logits[i, j] 表示：第 i 张图片和第 j 条文本的匹配分数。

步骤 喂给 CrossEntropyLoss 的矩阵 一行代表什么 一列代表什么 labels 的含义
Step 05 图片找文本 logits 一张图片 候选文本类别 labels[i] = i，表示 image i 应该选 text i。
Step 06 文本找图片 logits.T 一条文本 候选图片类别 labels[j] = j，表示 text j 应该选 image j。

Step 05 的核心代码是： 

image_to_text_probs = logits.softmax(dim=1)
per_image_loss = F.cross_entropy(logits, labels, reduction="none")
loss_i2t = per_image_loss.mean()

softmax(dim=1) 表示沿着每一行的列方向做 softmax。也就是：固定一张图片，让它在所有候选文本里分配概率。比如第 0 行就是： 

image 0 对所有 text 的 logits:
[9.9728, 3.5665, 1.6062]

softmax 后:
[0.9981, 0.0016, 0.0002]

因为 labels[0] = 0，正确答案是 text 0，所以这一行的 loss 是：

lossimage0 = -log(P(text 0 | image 0)) = -log(0.9981)

这里看起来只取了正确类别的概率，但 0.9981 是从整行 [9.9728, 3.5665, 1.6062] 做 softmax 得到的。也就是说，text 1 和 text 2 的分数已经通过 softmax 分母影响了 P(text 0 | image 0)。

reduction="none" 是为了教学：它不急着把 3 行 loss 平均，而是先把每一张图片各自的 loss 打印出来。最后 mean() 才得到 loss_i2t。

Step 06 没有重新计算相似度，它只是把同一张表换一个方向读： 

text_to_image_probs = logits.T.softmax(dim=1)
per_text_loss = F.cross_entropy(logits.T, labels, reduction="none")
loss_t2i = per_text_loss.mean()

为什么要 logits.T？因为 PyTorch 的 CrossEntropyLoss 习惯把“每一行”当成一个样本，把“每一列”当成类别。文本找图片时，样本应该变成文本，类别应该变成图片，所以需要转置： 

logits.T 的第 0 行:
text 0 对所有 image 的 logits

labels[0] = 0:
text 0 应该选 image 0

抓主线：Step 05 是“每张图片从所有文本里选正确文本”；Step 06 是“每条文本从所有图片里选正确图片”。两步共用同一张相似度矩阵，只是一个横着读，一个转置后再横着读。

8.3.1 配置里的 projection_dim、vision hidden_size、text hidden_size

真实脚本加载成功后，会打印类似： 

processor class = CLIPProcessor
model class = CLIPModel
projection_dim = 512
vision hidden_size = 768
text hidden_size = 512

这几个值属于不同层级，不能简单理解成“CLIP 每层都是 512 维”。

配置项 含义 它影响哪里的 shape
processor class = CLIPProcessor 说明 AutoProcessor 自动解析成了 CLIP 专用 processor。 负责图片预处理和文本 tokenizer，输出 pixel_values、input_ids、attention_mask。
model class = CLIPModel 说明加载的是 Hugging Face 的 CLIP 双塔模型。 内部包含 vision tower、text tower、两个 projection 层和 logit_scale。
projection_dim = 512 图文最终进入共享向量空间后的维度。 outputs.image_embeds.shape[-1] 和 outputs.text_embeds.shape[-1] 都是 512。
vision hidden_size = 768 视觉 Transformer 内部每个 image token 的向量宽度。 视觉塔中 patch token、class token、每层 hidden state 的最后一维是 768。
text hidden_size = 512 文本 Transformer 内部每个 text token 的向量宽度。 文本塔中 token embedding、每层 hidden state 的最后一维是 512。

对 openai/clip-vit-base-patch32 来说，图片侧大致是这条路径： 

pixel_values.shape = [num_images, 3, 224, 224]

patch embedding:
  [num_images, 49, 768]

加 class token:
  [num_images, 50, 768]

vision Transformer 每层 hidden state:
  [num_images, 50, 768]

取整图 pooled 向量:
  [num_images, 768]

visual_projection:
  [num_images, 768] -> [num_images, 512]

outputs.image_embeds:
  [num_images, 512]

这里的 49 来自 224 / 32 = 7，也就是 7 * 7 = 49 个 patch。再加 1 个 class token，所以视觉 Transformer 看到的是 50 个 image token。每个 token 的宽度是 768。

文本侧大致是这条路径： 

input_ids.shape = [num_texts, L]

token embedding:
  [num_texts, L, 512]

text Transformer 每层 hidden state:
  [num_texts, L, 512]

取 EOS / pooled 文本向量:
  [num_texts, 512]

text_projection:
  [num_texts, 512] -> [num_texts, 512]

outputs.text_embeds:
  [num_texts, 512]

关键结论：projection_dim = 512 只说明最终用于图文相似度计算的共享空间是 512 维；它不表示视觉塔内部每一层都是 512 维。这个模型里，视觉塔内部是 768 维，文本塔内部是 512 维，最后两边都通过 projection 层对齐到 512 维。

这段代码和前面最小 demo 的对应关系非常直接：

真实输出 shape 对应前面的概念
pixel_values [num_images, C, H, W] 图片经过 processor 后变成模型需要的归一化像素张量。
input_ids [num_texts, L] 候选文本经过 tokenizer 后变成 token id。
outputs.image_embeds [num_images, projection_dim] 真实 CLIP image encoder + projection 得到的整图向量。
outputs.text_embeds [num_texts, projection_dim] 真实 CLIP text encoder + projection 得到的整句向量。
outputs.logits_per_image [num_images, num_texts] 每张图片和每条候选文本的匹配分数。

9. AutoProcessor：把原始图片和文本整理成模型输入

Step 07 要拆的是 processor(...)。它不是模型，不负责理解语义；它像入口安检，把图片和文本整理成 CLIPModel 能吃的张量。

先立边界：AutoProcessor 不会输出 image_embeds 或 text_embeds。它只输出 pixel_values、input_ids、attention_mask 这类输入张量。真正的向量表示由 CLIPModel 的 image encoder 和 text encoder 算出来。

9.1 真实推理脚本里的这一行

encoded = processor(
    text=texts,
    images=image,
    return_tensors="pt",
    padding=True,
)

这行代码同时处理两种模态：images=image 进入图片预处理流程，text=texts 进入文本分词流程。最后返回一个字典，里面的 value 是 PyTorch Tensor。

输入字段 原始形态 processor 输出 送给谁
images PIL 图片 / 图片路径读取后的 RGB 图片 pixel_values CLIP image encoder
text 候选文本字符串列表 input_ids、attention_mask CLIP text encoder

9.2 图片侧：从图片到 pixel_values

真实 CLIP 的图片侧通常会做这些事。不同模型配置可能细节略有差异，但主线一致：

  1. 把图片转成 RGB。
  2. 按模型配置 resize 到指定尺寸。
  3. 必要时 center crop 到固定输入大小，例如 224 × 224。
  4. 把像素从图片格式转成浮点张量。
  5. 调整维度顺序，从 [H, W, C] 变成 [C, H, W]。
  6. 按 CLIP 的 mean/std 做 normalize。
  7. 加上 batch 维度，得到 [num_images, C, H, W]。
image
-> RGB image
-> resize / center crop
-> float tensor
-> [H, W, C] to [C, H, W]
-> normalize
-> pixel_values.shape = [num_images, 3, 224, 224]

注意，pixel_values 仍然不是 image embedding。它只是“整理干净的像素张量”。之后还要进入 image encoder，才会得到 outputs.image_embeds。

9.3 文本侧：从字符串到 input_ids

文本侧做的是你在 Day6 学过的 tokenizer 工作。候选文本先被分成 token，再映射成词表里的整数 ID。 

texts = [
    "a red square on a white background",
    "a blue circle on a white background",
    "a photo of a dog on grass",
]

tokenizer(texts)
-> input_ids.shape = [num_texts, L]
-> attention_mask.shape = [num_texts, L]
张量 含义 关键点
input_ids 每条文本被 tokenizer 切分后，对应到词表里的整数编号。 整数 ID 本身不是语义向量，只是查 embedding 表的索引。
attention_mask 标记哪些位置是真实 token，哪些位置是 padding。 1 表示真实 token，0 表示补齐位置。

9.4 为什么需要 padding=True

候选文本长短不一样，但一个 batch 里的 input_ids 必须能堆成整齐矩阵。如果第一句话有 8 个 token，第二句话有 6 个 token，就需要把短句补到同样长度。 

text 0 tokens: [id, id, id, id, id, id, id, id]
text 1 tokens: [id, id, id, id, id, id, pad, pad]

input_ids.shape      = [2, 8]
attention_mask.shape = [2, 8]

attention_mask 的作用就是告诉 text encoder：补齐的 pad 位置不是有效内容，不要把它当成真实文字理解。

9.5 return_tensors="pt" 是什么意思

pt 是 PyTorch 的缩写。设置 return_tensors="pt" 后，processor 会直接返回 PyTorch Tensor，而不是 Python list 或 NumPy array。 

encoded = {
    "pixel_values": tensor([...]),   # torch.Tensor
    "input_ids": tensor([...]),      # torch.Tensor
    "attention_mask": tensor([...]), # torch.Tensor
}

这也是为什么真实脚本后面可以直接写： 

outputs = model(**encoded)

这里的 **encoded 是 Python 的字典展开语法，等价于： 

outputs = model(
    pixel_values=encoded["pixel_values"],
    input_ids=encoded["input_ids"],
    attention_mask=encoded["attention_mask"],
)

9.6 processor 和 model 的边界

本阶段最重要的一句话：AutoProcessor 是输入整理器，CLIPModel 才是语义编码器。processor 输出的是“可喂给模型的张量”，model 输出的才是“可比较的图文向量和相似度分数”。

10. CLIPModel.forward()：真实模型内部主线

前面你已经看懂了真实推理脚本。现在把焦点收窄到这一行：outputs = model(**encoded)。它不是魔法，本质上就是图片走 vision tower，文本走 text tower，然后两边投影到同一个空间，最后算相似度矩阵。

源码依据：本节按当前环境里的 transformers.models.clip.modeling_clip.CLIPModel.forward 主线整理。为了学习清晰，下面使用等价伪代码，不逐行复制源码。

10.1 顶层 forward 做了哪几件事

vision_outputs = get_image_features(pixel_values)
text_outputs   = get_text_features(input_ids, attention_mask)

image_embeds = vision_outputs.pooler_output
text_embeds  = text_outputs.pooler_output

image_embeds = L2_normalize(image_embeds)
text_embeds  = L2_normalize(text_embeds)

logits_per_text  = text_embeds @ image_embeds.T
logits_per_text  = logits_per_text * exp(logit_scale)
logits_per_image = logits_per_text.T

这段伪代码就是整个 CLIP 推理的骨架。注意顺序：先分别编码图片和文本，再把整图向量、整句向量取出来，然后做 L2 归一化，最后用矩阵乘法得到相似度分数。

10.2 图片路径：get_image_features(pixel_values)

图片侧先进入 vision_model。对于 openai/clip-vit-base-patch32，视觉塔内部宽度是 768，所以进入 projection 之前都是视觉塔自己的维度。 

pixel_values
  [num_images, 3, 224, 224]

CLIPVisionEmbeddings:
  Conv2d patch embedding
  -> [num_images, 49, 768]

  + class token
  -> [num_images, 50, 768]

  + position embedding
  -> [num_images, 50, 768]

vision Transformer encoder:
  -> last_hidden_state [num_images, 50, 768]

取 class token:
  pooled_output = last_hidden_state[:, 0, :]
  -> [num_images, 768]

visual_projection:
  [num_images, 768] -> [num_images, 512]

不要把 50 理解成 50 个 patch：openai/clip-vit-base-patch32 的输入是 224 × 224，patch size 是 32，所以高方向切出 224 / 32 = 7 个 patch，宽方向也是 7 个 patch，总 patch 数是 7 × 7 = 49。再额外拼上 1 个 class token，序列长度才变成 49 + 1 = 50。

更底层一点，视觉侧的 patch embedding 可以理解成： 

Conv2d(
    in_channels=3,
    out_channels=768,
    kernel_size=32,
    stride=32,
)

pixel_values:       [num_images, 3, 224, 224]
Conv2d output:      [num_images, 768, 7, 7]
flatten + transpose:[num_images, 49, 768]
add class token:    [num_images, 50, 768]

这里的 768 是视觉塔的 hidden_size，也就是模型架构配置里的“内部向量宽度”。它是训练前选定的超参数，不是训练过程中被 optimizer 学出来的那个数字。真正被训练出来的是围绕这个宽度的一堆权重值，例如 patch embedding 的卷积核权重、attention 里的 Q/K/V 矩阵、MLP 矩阵、class token、position embedding 等。

图片路径变量 典型 shape 含义
pixel_values [num_images, 3, 224, 224] processor 整理好的图片张量。
last_hidden_state [num_images, 50, 768] 视觉 Transformer 输出的每个 image token 表示。
pooled_output [num_images, 768] 取第 0 个 class token，作为整张图的汇总向量。
visual_projection(pooled_output) [num_images, 512] 把视觉塔内部向量投影到 CLIP 共享空间。

10.3 文本路径：get_text_features(input_ids, attention_mask)

文本侧进入 text_model。这个模型的文本塔 hidden size 正好是 512，但这仍然分两层含义：Transformer 内部 hidden state 是 512，最后共享空间的 projection 结果也是 512。 

input_ids
  [num_texts, L]

CLIPTextEmbeddings:
  token embedding + position embedding
  -> [num_texts, L, 512]

text Transformer encoder:
  -> last_hidden_state [num_texts, L, 512]

取 EOS / EOT token 对应位置:
  pooled_output -> [num_texts, 512]

text_projection:
  [num_texts, 512] -> [num_texts, 512]

这里 text_projection 输入输出都是 512，但它仍然是一个可学习线性层。不要因为维度没变，就误以为它什么都没做；它会旋转、缩放、重新组织这个向量，让文本侧更适合和图片侧比较。

10.4 为什么 forward 里还要再 L2 normalize

projection 后得到的是共享空间里的图文向量，但它们的长度未必相同。CLIP 会把每个整图向量、整句向量都除以自己的 L2 长度：

image_embeds = image_embeds / ||image_embeds||2
text_embeds = text_embeds / ||text_embeds||2

做完这一步，每一行向量长度约等于 1。后面的点积就主要表示方向相似度，也就是 cosine similarity。

10.5 logits_per_text 和 logits_per_image

源码里先算文本到图片方向： 

logits_per_text = text_embeds @ image_embeds.T
logits_per_text = logits_per_text * exp(logit_scale)

如果有 num_texts = 4，num_images = 1： 

text_embeds.shape       = [4, 512]
image_embeds.T.shape    = [512, 1]
logits_per_text.shape   = [4, 1]
logits_per_image.shape  = [1, 4]

然后源码用转置得到图片到文本方向： 

logits_per_image = logits_per_text.T

这就是为什么真实推理脚本里用： 

probabilities = outputs.logits_per_image.softmax(dim=1)

因为当前任务是“一张图片从多条候选文本里选最匹配的一条”，所以要在 logits_per_image 的文本候选维度上做 softmax。

10.6 这和前面的 toy demo 如何对齐

toy demo 真实 CLIP forward 关系
image_raw vision_model + visual_projection toy demo 直接手写图片向量；真实模型从像素算出来。
text_raw text_model + text_projection toy demo 直接手写文本向量；真实模型从 token id 算出来。
F.normalize(..., dim=1) forward 里的 L2 normalize 两边都是把每一行向量变成单位长度。
image_embeddings @ text_embeddings.T logits_per_image 两边都是图片对文本的匹配分数表。

本阶段最重要的一句话：CLIPModel.forward() 不是“直接把图片和文字混在一起理解”，而是先分别编码成整图向量和整句向量，再投影到同一个 512 维空间，归一化后用矩阵乘法计算图文匹配分数。

11. 同一个向量空间

“同一个向量空间”这句话很抽象，可以先理解成：图片和文字最终都被翻译成同一种坐标系里的点。

训练前

图片向量和文本向量是随机或不对齐的。即使语义匹配，也不一定靠近。

训练目标

匹配的图文向量拉近，不匹配的图文向量推远。

训练后

“狗的图片”和“狗的文本”在向量空间中更接近。

如果图文向量都已经归一化，常见相似度可以写成点积：

similarity(image, text) = image_embedding · text_embedding

这里的点积暂时不用展开公式。先记住：两个向量方向越接近，分数越高。

12. 小例子

假设我们已经有一个训练好的 CLIP。现在给它 1 张图片和 3 条文本，它会做下面的事： 

image_embedding.shape = [D]
text_embeddings.shape = [3, D]

scores = image_embedding @ text_embeddings.T
scores.shape = [3]

假设输出分数是：

文本 相似度分数 解释
一只小狗在草地上。 0.82 最高，最匹配。
一辆红色汽车在路边。 0.13 不太匹配。
一碗面条放在桌上。 0.05 更不匹配。

当前阶段只需掌握：CLIP 不是直接输出一句话，也不是生成图片。它最核心的能力是判断图片和文本在语义上有多接近。

13. Day9 收口检查点

Day9 主任务已经完成。收口时只需要确认下面这些主线都能讲通。

  1. CLIP 的目标是把图片和文本映射到同一个向量空间。
  2. Image Encoder 负责把图片变成 image_embedding。
  3. Text Encoder 负责把文本变成 text_embedding。
  4. 图文是否匹配，可以先通过两个向量的相似度来判断。
  5. 匹配图文应该更近，不匹配图文应该更远。
  6. 图片塔和文本塔内部 shape 可以不同，但最终都要输出 [B, D]。
  7. D 是共享向量空间的维度，后面计算相似度矩阵时会用到。
  8. image_embeddings[b] 是第 b 张图片的整图向量，不是某个 patch 的向量。
  9. image_embeddings @ text_embeddings.T 会得到 [B, B] 的图文相似度矩阵。
  10. 矩阵第 i 行第 j 列表示第 i 张图和第 j 条文本的匹配分数。
  11. 如果 batch 按图文对排列，那么对角线就是正确匹配，非对角线就是错误匹配。
  12. 图片找文本：CrossEntropyLoss(S, labels)。
  13. 文本找图片：CrossEntropyLoss(S.T, labels)。
  14. CLIP loss 通常是两个方向 loss 的平均。
  15. 梯度会让对角线分数上升，让非对角线分数下降，并继续影响两个 encoder 的参数。
  16. 最小 demo 已经把 [B, D] -> [B, B] -> labels -> loss -> backward() 跑通。
  17. 真实 CLIP 推理中，outputs.image_embeds 和 outputs.text_embeds 是真实模型算出来的共享空间向量。
  18. outputs.logits_per_image 就是真实模型给出的图片对文本候选的匹配分数。
  19. AutoProcessor 只负责把图片和文本整理成 pixel_values、input_ids、attention_mask。
  20. pixel_values 和 input_ids 不是 embedding，真正的 embedding 来自 CLIPModel。
  21. CLIPModel.forward() 顶层会分别调用图片路径和文本路径，再取出 image_embeds、text_embeds。
  22. 视觉塔内部 hidden size 可以是 768，但 visual_projection 会把整图向量投影到 projection_dim = 512。
  23. 文本塔内部 hidden size 是 512，text_projection 会把整句向量整理到同一个 512 维共享空间。
  24. 真实 forward 中会对图文向量做 L2 normalize，再计算 logits_per_text 和 logits_per_image。
