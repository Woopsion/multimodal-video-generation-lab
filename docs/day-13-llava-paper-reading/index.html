4. LLaVA 架构主线

LLaVA 论文里的核心架构可以先压缩成一句话：用 CLIP 的视觉编码器读图，用一个线性投影层把视觉特征接到 LLM 的词向量空间，再让 Vicuna 根据图片和问题生成答案。

image
-> CLIP ViT-L/14 vision encoder
-> visual features
-> projection matrix
-> language embedding space
-> Vicuna / LLM
-> answer tokens

4.1 Step 01：论文定位

LLaVA 的价值在于把两个已经强大的东西连接起来：视觉侧用 CLIP，语言侧用 Vicuna。论文真正关心的是连接以后如何训练，让语言模型不只是会聊天，还能围绕图片内容完成指令跟随。

当前必须掌握：LLaVA 的任务目标不是 CLIP 式图文匹配，而是视觉条件下的对话和指令跟随。它的输出是自然语言回答，不是相似度分数。

4.2 Step 02：三个组件

组件论文里的角色和 Day12 的对应关系
CLIP ViT-L/14固定或预训练好的视觉编码器，负责把图片变成视觉特征。vision encoder
Projection matrix把视觉特征映射到语言模型词向量空间。projector
Vicuna作为语言模型主体，根据视觉上下文和文本指令生成回答。LLM decoder
你的 Step 01-02 回答已经过关：CLIP 更像输出图文匹配分数，LLaVA 的目标是围绕图片和文本生成自然语言回答。projection matrix 不是看图模块，它负责把视觉特征投影到 LLM 的词向量空间，让图片信息能作为上下文 token 参与后续生成。

4.3 Step 03：视觉指令数据

现在进入 LLaVA 论文真正有代表性的部分：视觉指令数据。普通 image-caption 数据通常只长这样：一张图对应一句描述。它能教模型“这张图大概是什么”，但不太能教模型“用户问不同问题时应该怎样回答、怎样追问、怎样解释、怎样做推理”。

Caption 数据教什么

image -> caption 更像描述任务。模型学到的是把图片压缩成一句或几句说明，例如“一个人在雨中撑伞”。

这对视觉语言对齐有用，但互动性弱。用户问数量、位置、原因、风险、下一步动作时，单句 caption 往往不够。

Instruction 数据教什么

image + question -> answer 更像视觉助手任务。模型学到的是按照用户问题选择相关视觉信息，再用自然语言回答。

这才对应 Day12 真实推理里的输入输出：图片路径和问题文本进去，解码后的文字回答出来。

关键纠偏：原始 LLaVA 的数据生成阶段里，language-only GPT-4 没有直接读取图片像素。论文把图像 caption、物体类别、bounding box 等元信息组织成文本化场景描述，再让 GPT-4 根据这些文本信息生成视觉指令样本。真正训练 LLaVA 时，样本仍然绑定真实图像，模型学习的是 image + instruction -> answer。

和 language-only GPT-4 的关系

GPT-4 不是 LLaVA 推理时的一部分，也不是 LLaVA 的视觉编码器。它更像训练前的数据标注员或教材编写员：根据已有的图片文本信息，生成更接近人类视觉对话的问答样本。

GPT-4 做的是数据生成

输入给 GPT-4 的不是图片像素，而是 caption、物体类别、bounding box 等文本化场景信息。GPT-4 把这些信息改写成问题、回答、详细描述和推理样本。

caption + objects + boxes
-> language-only GPT-4
-> visual instruction samples

LLaVA 学的是视觉条件回答

训练 LLaVA 时，样本仍然绑定真实图片。模型输入是真实图片加用户指令，目标输出是 GPT-4 生成的回答文本，所以 LLaVA 要学会让图片特征影响语言生成。

real image + instruction
-> LLaVA
-> assistant answer
能不能叫蒸馏：可以粗略理解成“数据层面的蒸馏”或“GPT-4 伪标注”，因为学生模型在学习 GPT-4 写出来的答案风格和指令格式。但它不是经典 logits 蒸馏：GPT-4 没有把每个 token 的概率分布直接交给 LLaVA，也没有在推理时参与计算。更准确的说法是 GPT-assisted visual instruction data generation。
不要把它理解成更活跃的 caption：caption 主要是描述图片，而视觉指令数据要覆盖“问什么答什么”。它包含普通问答、详细描述和复杂推理，目标是把模型训练成视觉助手，而不只是训练成会写长描述的 caption 生成器。
数据类型它训练模型学会什么直观例子
Conversation围绕图片进行多轮或单轮问答，回答物体、数量、动作、位置、相对关系等明确问题。“图里的人在做什么？” -> “他正撑着伞在雨中行走。”
Detailed description生成更完整的图片描述，不只是一句短 caption，而是把场景、主体、背景、关系展开。“请详细描述这张图片。” -> 多句场景说明。
Complex reasoning基于视觉事实继续做常识推理或步骤化解释，回答“为什么、可能会怎样、需要注意什么”。“为什么这个人可能走得比较困难？” -> 结合下雨、伞、路况做推理。
当前必须掌握：视觉指令数据不是为了让模型“看见更多图片”这么简单，而是为了把视觉信息改造成 LLM 熟悉的指令跟随格式。LLaVA 借助 GPT-4 把静态图文数据改造成对话、详细描述和复杂推理三类训练样本。
理解即可：具体 prompt 模板、COCO 样本筛选细节、noun-verb 频次可视化暂时不需要深挖。现阶段先抓住“caption 不够互动，instruction 数据塑造回答行为”这条主线。

4.4 Step 04：两阶段训练

这一节先不要背术语。LLaVA 的两阶段训练本质上是在回答两个问题：第一，CLIP 产生的视觉特征怎么变成 LLM 能读懂的向量；第二，LLM 怎么学会把这些视觉向量当作上下文来回答用户问题。

先定义“训练”和“冻结”：训练一个模块，就是让 loss 通过反向传播产生梯度，再由优化器修改这个模块的参数。冻结一个模块，就是这个模块仍然参与前向计算，但它的参数不被优化器更新。冻结不等于不用它；冻结只是“不改它”。
模块Stage 1 状态Stage 2 状态怎么理解
CLIP vision encoder冻结冻结一直负责看图，把图片变成视觉特征；但它的视觉能力不被改动。
Projection matrix / projector训练继续训练桥接层，把 CLIP 的视觉特征转换成 LLM hidden size 的 image tokens。
Vicuna / LLM冻结训练第一阶段不动语言模型；第二阶段让它学会使用 image tokens 来回答问题。

什么叫只训练 projection matrix

projection matrix 可以先理解成一个线性层。CLIP 输出的视觉特征维度和 LLM 的词向量维度不一致，所以中间需要一个可学习矩阵把它们接起来。

visual_features = frozen_clip(image)
image_tokens    = visual_features @ W_proj + b
# Stage 1 只更新 W_proj 和 b
# CLIP 参数不变，LLM 参数不变

这不是说模型只跑 projector。完整前向过程仍然会经过 CLIP、projector、LLM。区别在于：反向传播之后，优化器只修改 projector 的参数，CLIP 和 LLM 的参数保持原样。

非常关键：冻结模块仍然“工作”。冻结 CLIP 不代表模型不看图；冻结 LLM 不代表模型不生成文字。它们都参与计算，只是参数不被训练更新。

CC3M 是什么

CC3M 是 Conceptual Captions 3M 的简称，是一个大规模图片-文本描述数据集。它从网页中的图片和 alt-text 中抽取、清洗出图片 caption，用于图像描述和视觉语言预训练。LLaVA 第一阶段不是使用完整 CC3M，而是使用过滤后的 595K image-caption pairs。

CC3M 样本长什么样

image: 一张真实网页图片
caption: a person riding a bike on a street

它主要提供“图片对应一句描述”。这适合做初步对齐，但不适合直接训练复杂问答。

为什么 Stage 1 用它

Stage 1 不需要模型学会复杂对话，只需要先让视觉特征能进入 LLM 的表示空间。caption 数据简单、数量大、成本低，适合做接口预热。

Stage 1：Feature Alignment Pretraining

第一阶段的目标不是让模型变成视觉助手，而是把“视觉接口”接通。此时 projector 还没有学会如何把 CLIP 特征翻译成 LLM 可读的 image tokens，所以先用简单 caption 任务来训练这个桥。

1. 输入真实图片
2. frozen CLIP 把图片编码成 visual features
3. trainable projector 把 visual features 转成 LLM hidden size
4. frozen LLM 根据 image tokens 生成 caption
5. loss 主要算在 caption tokens 上
6. optimizer 只更新 projector
为什么这样设计解释
为什么冻结 CLIPCLIP 已经有稳定的看图能力。第一阶段只需要使用它的视觉特征，不希望为了 caption 任务把视觉编码器整体改乱。
为什么冻结 LLMLLM 已经有语言生成能力。第一阶段只是在学习“视觉特征如何送进语言模型”，不需要改变语言模型本体。
为什么只训练 projector如果桥还没接好就同时改 CLIP 和 LLM，训练目标会变得混乱。只训练 projector 可以把问题缩小成“找到一个合适的映射”。
这一阶段学到什么projector 学会把 CLIP 视觉特征变成一串更像 LLM token embedding 的 image tokens。

Stage 2：Visual Instruction Tuning

第二阶段才开始训练“视觉助手行为”。此时 projector 已经有初步对齐能力，模型能把图片特征塞进 LLM。接下来要解决的是：面对用户问题时，LLM 应该怎样使用这些 image tokens 来回答。

1. 输入真实图片 + 用户问题
2. frozen CLIP 把图片编码成 visual features
3. trainable projector 生成 image tokens
4. trainable LLM 同时读取 image tokens 和 question tokens
5. LLM 预测 assistant answer tokens
6. optimizer 更新 projector + LLM，仍然不更新 CLIP
为什么这样设计解释
为什么 Stage 2 还冻结 CLIP视觉侧继续使用稳定的 CLIP 特征，降低训练成本和过拟合风险。LLaVA 的重点不是重新训练视觉塔。
为什么继续训练 projectorStage 2 的任务比 caption 更复杂，projector 需要继续适配问答、详细描述和推理场景。
为什么要训练 LLM只训练 projector 只能调整“图像特征怎么送进来”，但不能充分改变 LLM 的行为。LLM 需要学会在注意力计算中使用 image tokens、按用户问题筛选视觉信息、生成符合助手格式的回答。
这一阶段学到什么模型从“能接收图片”变成“能围绕图片进行指令跟随”。

loss 到底算在哪里

训练样本里通常有图片、用户问题、助手答案。图片和用户问题是条件上下文，模型真正要学的是助手答案，所以 loss 主要算在 assistant answer tokens 上。

context = image_tokens + user_question_tokens
label   = assistant_answer_tokens
loss    = model answer 和标准 answer 的差距
如果 loss 算在用户问题上会怎样：那模型会被训练去复述或预测用户问题，而不是学习回答问题。我们真正关心的是：给定图片和问题，模型能不能生成正确的 assistant answer。
关于 end-to-end 的精确理解：论文把 Stage 2 称为 Fine-tuning End-to-End，但这不等于所有模块都训练。更准确地说，图像和文本作为统一序列进入模型，梯度用于更新 projector 和 LLM；CLIP vision encoder 仍然保持冻结。

必须深入掌握

  • 冻结不是不用，而是不更新参数。
  • Stage 1 是接口对齐：只训练 projector。
  • Stage 2 是行为塑造：训练 projector + LLM。
  • CLIP vision encoder 两个阶段都冻结，但一直负责提取视觉特征。
  • loss 主要作用在 assistant answer tokens 上。

理解即可

  • CC3M 的完整清洗细节。
  • 具体学习率、batch size、epoch 数。
  • 具体 prompt 模板和 <STOP> 标记。
  • ScienceQA 的单独组织方式。
一句话收束：Stage 1 让“视觉特征能进入语言模型”；Stage 2 让“语言模型学会根据视觉特征回答用户问题”。

4.5 Step 05：CLIP 与 LLaVA 到底差在哪里

CLIP 和 LLaVA 都能处理图片与文本，但它们解决的不是同一个问题。最核心的区别是：CLIP 学习“图片和文本是否匹配”，LLaVA 学习“看到图片并理解问题以后，下一个回答 token 应该是什么”。

先记住一句话：CLIP 是跨模态表征与匹配模型；LLaVA 是以视觉信息为条件的自回归语言生成模型。LLaVA 使用了 CLIP 的视觉编码器，但在它后面增加 projector 和 LLM，改变了整个系统的任务目标。

第一层：输入和输出不同

比较项CLIPLLaVA
典型输入一批图片 + 一批候选文本一张图片 + 用户问题或指令
核心输出图文相似度分数或 embedding一个接一个生成的自然语言 token
直接回答问题吗不能直接生成开放式回答可以生成描述、问答和推理文本
最擅长的任务检索、零样本分类、图文匹配视觉问答、图片描述、视觉对话

CLIP 的计算路径

image -> image encoder -> image embedding
text  -> text encoder  -> text embedding
                    |
             cosine similarity
                    |
              matching score

CLIP 会把图片和文本分别压缩为全局向量，再计算相似度。它回答的是“这段文字和这张图有多匹配”。

LLaVA 的计算路径

image -> CLIP vision encoder
      -> patch features -> projector
      -> image tokens + question tokens
      -> LLM -> answer tokens

LLaVA 保留较丰富的视觉 token，把它们与问题 token 一起送入 LLM。它回答的是“在这张图和这个问题作为上下文时，应该生成什么回答”。

第二层：训练目标不同

模型最终会学会什么，主要由训练目标决定。CLIP 和 LLaVA 的组件虽然有重叠，但优化的 loss 不同，因此形成了不同能力。

模型训练信号模型被奖励的行为
CLIP对比学习 loss：正确图文对靠近，错误图文对远离产生适合比较和检索的视觉、文本表示
LLaVA Stage 1caption token prediction loss让 projector 把视觉特征对齐到 LLM 可用的表示空间
LLaVA Stage 2assistant answer token prediction loss根据图片与指令生成符合任务要求的自然语言回答
不要混淆“使用 CLIP”和“就是 CLIP”：LLaVA 里的 CLIP vision encoder 只负责提取视觉特征。CLIP 原本的 text encoder 和图文相似度输出头并不是 LLaVA 回答问题的主体；回答来自 projector 后面的 Vicuna / LLM。

第三层：同一张图片，两者会怎样处理

假设图片中有一个孩子穿着雨衣，在积水旁拿着一把红伞。

给 CLIP 候选文本

A. a child holding a red umbrella
B. a dog running on the beach
C. a train arriving at a station

CLIP 可以给 A 更高的相似度。它擅长从给定候选中判断哪个文本最匹配图片。

向 LLaVA 提问

用户：孩子为什么可能穿着雨衣？
助手：因为地面有积水且孩子拿着伞，
      场景很可能正在下雨或刚下过雨。

LLaVA 不只选择标签，而是结合视觉事实、问题意图和语言知识生成完整回答。

CLIP 能不能做分类

可以。零样本分类常把类别改写成文本提示，例如 a photo of a cat、a photo of a dog，然后比较图片与各类别文本的相似度，最高分对应预测类别。

image_embedding 与 cat_prompt_embedding 的相似度 = 0.82
image_embedding 与 dog_prompt_embedding 的相似度 = 0.31
=> 预测为 cat
但这仍然不是生成式问答：类别和候选提示通常需要事先给出。CLIP 是在候选集合里比较；LLaVA 可以针对开放式问题组织新的回答 token。两者不是“弱模型和强模型”的简单关系，而是任务形式不同。

为什么 LLaVA 不直接丢掉 CLIP

因为 CLIP 已经通过大规模图文对学习了很强的视觉语义表示。LLaVA 没必要从零学习边缘、物体、场景和图文概念关系，而是复用 CLIP 作为视觉塔，再把训练资源集中在跨模态连接和视觉指令跟随上。

必须深入掌握

  • CLIP 输出 embedding / 相似度，LLaVA 输出自然语言 token。
  • CLIP 的核心训练目标是对比学习，LLaVA 的核心生成目标是 next-token prediction。
  • LLaVA 只复用 CLIP 的视觉编码能力，回答由 projector + LLM 完成。
  • 同一个视觉 encoder 放入不同训练架构，会服务于不同任务。

理解即可

  • CLIP 对比损失的完整数学推导。
  • temperature 参数与对称交叉熵细节。
  • 不同 CLIP backbone 的性能差异。
  • 检索系统的向量数据库工程实现。
Step 05 收束：CLIP 负责学习“视觉和语言如何在语义上对齐”；LLaVA 在这个视觉基础上进一步学习“如何围绕图片遵循指令并生成回答”。

4.6 Step 06：5 分钟讲稿与最终总结

现在把 Day13 压缩成一段可以复述的完整主线。重点不是背论文细节，而是能够从“为什么需要 LLaVA”一路讲到“它是如何训练出来的”。

5 分钟复述框架

  1. 任务定位：CLIP 擅长图文匹配，LLaVA 的目标是围绕图片遵循用户指令并生成自然语言回答。
  2. 模型架构：CLIP ViT-L/14 负责提取视觉特征，projection matrix 把视觉特征映射到 LLM hidden size，Vicuna 根据 image tokens 与问题 tokens 生成答案。
  3. 数据构造：language-only GPT-4 根据 caption、物体类别和 bounding box 等文本化场景信息生成 conversation、detailed description、complex reasoning 三类视觉指令数据。
  4. Stage 1：冻结 CLIP 和 LLM，只训练 projector，用过滤后的 CC3M caption 数据完成 feature alignment。
  5. Stage 2：继续冻结 CLIP，训练 projector + LLM，用视觉指令数据塑造视觉问答和指令跟随行为。
  6. 训练目标：图片与问题作为上下文，loss 主要计算在 assistant answer tokens 上，本质仍是条件化的 next-token prediction。
最终心智模型：CLIP 提供已经学好的视觉语义表示，projector 负责跨空间连接，LLM 负责理解指令与组织回答；视觉指令微调让这三个部分形成一个可对话的视觉助手。
