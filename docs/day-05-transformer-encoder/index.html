Day 5 / Transformer Encoder

从 token 到 attention 的第一层理解

这一页只讲清楚四件事：embedding 是什么，position embedding 为什么存在，Q/K/V 是如何生成的，self-attention 如何把一个 token 更新成上下文向量。

  • 所有“信息”和“内容”在模型里都是向量，也就是一组浮点数。
  • token embedding 和 position embedding 都是可学习参数表。
  • attention 的输出是 forward 中的新向量，不是直接修改参数。

1. Embedding：不是计算语义，而是查一张可训练表

token id 只是编号，本身没有数值大小意义。Embedding 的作用是把这个编号映射成一个模型能处理的向量。

先抓住一句话： token embedding 是一张参数表。输入 token id 后，模型取出这张表里的对应行。
xt = E[token_idt]
符号 含义 类比前几天的知识
E token embedding 表，shape 是 [vocab_size, embed_dim] 和 Linear 的 weight 一样，是可学习参数。
token_id_t 第 t 个位置的 token 编号 像 MNIST label 一样，是编号，不是连续数值。
x_t 第 t 个 token 查表后得到的向量 相当于模型内部对这个 token 的初始特征。

这张表一开始通常是随机初始化。训练时，某个 batch 用到了哪些 token，那些 token 对应的行就会收到梯度并被更新。 所以 embedding 不是人手写出来的语义字典，而是通过任务 loss 慢慢学出来的参数。

2. Position Embedding：给每个位置一张可训练“坐标标签”

token embedding 告诉模型“这个 token 是谁”。position embedding 告诉模型“这个 token 在哪里”。

token id

表示词表里的编号，例如“我”可能是 12，“打”可能是 35。

position id

表示序列里的位置编号，例如第一个位置是 0，第二个位置是 1。

如果一句话有 5 个 token，那么它的位置编号就是：

position ids = [0, 1, 2, 3, 4]

这不是 token 的编号，而是“第几个位置”。所以 position embedding 表 P 也可以理解成：第 0 个位置有一条向量，第 1 个位置有一条向量，第 2 个位置有一条向量。

xt = E[token_idt] + P[t]
句子 第 0 个位置 第 1 个位置 第 2 个位置
我 打 你 E[我] + P[0] E[打] + P[1] E[你] + P[2]
你 打 我 E[你] + P[0] E[打] + P[1] E[我] + P[2]
为什么这件事重要： “我 打 你”和“你 打 我”包含同样的 token，但顺序不同，意思完全不同。 position embedding 让同一个 token 出现在不同位置时，进入 Transformer 的向量不同。

3. Q/K/V：不是三种文字信息，而是三组向量视角

Q、K、V 都是向量。所谓“想找什么”“提供什么标签”“真正内容”，都是帮助理解的比喻，底层实际存在形式就是一组浮点数。

qt = xtWQ    kt = xtWK    vt = xtWV
符号 底层形式 通俗理解
x_t 第 t 个 token 进入 attention 前的向量 “这个 token 是谁 + 它在哪里”的当前表示
W_Q 共享的可学习参数矩阵 把 x 转成“我想找什么”的 query 视角
W_K 共享的可学习参数矩阵 把 x 转成“我如何被匹配”的 key 视角
W_V 共享的可学习参数矩阵 把 x 转成“真正被汇总的内容” value 视角
关键点： 不是每个 token 各自拥有一套 WQ/WK/WV。 同一层 attention 共享这三套矩阵。每个 token 用自己的 xt 通过同一套矩阵，生成自己的 q/k/v。

4. Self-Attention：用权重把所有 V 混成当前 token 的新向量

这一步只是在 forward 里产生新的上下文向量，不是 optimizer.step 那种参数更新。

score(t, j) = qt · kj

t 表示当前正在更新的 token 位置； j 表示被它查看的 token 位置。 点积 q_t · k_j 用来衡量“第 t 个 token 的 query”和“第 j 个 token 的 key”匹配程度。

attention_weight(t, j) = exp(score(t, j)) Σr exp(score(t, r))

exp(x) 就是 e^x。 它让分数变成正数；分母把同一行的所有正数加起来，使最后权重总和为 1。

outputt = Σj attention_weight(t, j) · vj

这句话展开就是：第 t 个 token 的新向量，等于它对所有 token 的 value 向量做加权求和。

一个 3 token、2 维 value 的数字例子

v0 = [1, 0]   v1 = [0, 2]   v2 = [3, 1]
第 0 个 token 的 attention 权重 = [0.70, 0.20, 0.10]
output0 = 0.70 · [1, 0] + 0.20 · [0, 2] + 0.10 · [3, 1]
= [0.70, 0.00] + [0.00, 0.40] + [0.30, 0.10]
= [1.00, 0.50]
这里的“更新自己”是什么意思： 原来的 xt 没有被原地改掉。attention 产生了一个新的 outputt， 它混入了其他 token 的 value 信息。参数更新仍然发生在训练阶段的 optimizer.step。

5. Multi-Head：不是机械切原始 x，而是投影后拆成多个关系子空间

Multi-Head 的核心是让模型用多套 attention 权重同时看序列关系。每个 head 可以学到不同的关注方式。

输入

x.shape = [batch, seq_len, embed_dim]

拆 head

head_dim = embed_dim / num_heads

输出

合并后仍回到 [batch, seq_len, embed_dim]

embed_dim = num_heads × head_dim

例如：

embed_dim = 8, num_heads = 2
head_dim = 8 / 2 = 4

先投影

输入 x 经过 Linear 得到 q/k/v。此时每个还是 embed_dim 维。

再拆 head

把最后一维 reshape 成 num_heads × head_dim，让每个 head 单独算 attention。

最后合并

每个 head 输出 head_dim 维，拼接后回到 embed_dim 维。

追加问答 01 / 2026-05-14

为什么要设计 Q/K/V，而不是直接拿 token 向量互相算？

你的问题本质是：我已经知道 Q/K/V 怎么算了，但为什么 Transformer 要这样设计？这是人类为了方便理解起的名字，还是模型结构本身真的需要这种分工？

先给结论： Q/K/V 这三个名字带有帮助人类理解的比喻，但 Q/K/V 的分工不是随便编出来的。 它是一种真实的架构设计：用 Q 和 K 决定“看谁”，用 V 决定“拿什么内容回来”。

1. Q/K/V 是人类理解用的比喻吗？

是，也不完全是。

“Query、Key、Value”这三个词确实是人类为了理解而借用的概念。它们很像数据库检索：

Query：我拿什么去查找
Key：每条记录用什么被匹配
Value：匹配后真正取回来的内容

但在 Transformer 里，Q/K/V 不是文字、不是标签、不是人类写好的规则。它们的实际存在形式都是向量：

qt、kt、vt 都是一组浮点数

所以更准确地说：

Q/K/V 的名字是理解类比；
Q/K/V 的计算结构是真实架构；
Q/K/V 的具体含义由训练学出来。

2. 这是设计者的一种“哲学”吗？

可以说有设计思想，但不是玄学式哲学。更工程化的说法是：

Transformer 的 Q/K/V 是一种 inductive bias。 也就是设计者提前规定了一种适合序列关系建模的计算方式，然后让模型通过训练去学习这套计算方式里的参数。

类比 Day 4 的 CNN：

结构 设计者规定了什么 模型训练学什么
CNN 用小卷积核在图片上滑动，优先建模局部空间结构。 每个卷积核具体检测什么图案。
Transformer Attention 每个 token 可以对所有 token 分配权重，再汇总信息。 Q/K/V 参数如何产生有用的关注关系。

所以不是设计者手工告诉模型：

head 1 必须学主语
head 2 必须学地点
W_Q 的第 3 维必须表示某种语法

设计者只是规定了一个可训练的计算框架：

x → Q/K/V → 分数 → softmax 权重 → 加权汇总 V → 新 token 向量

至于这些参数最后学出什么模式，是训练数据和 loss 共同逼出来的。

3. 为什么不是 q 直接乘 v？

这里要纠正一个容易混的点：attention 里不是用 q 直接去乘各个 v 来决定关注谁。

正确流程是：q 和 k 算匹配分数，然后用分数产生的权重去加权 v
score(t, j) = qt · kj
weight(t, j) = softmax(score(t, j))
outputt = Σj weight(t, j) · vj

这样设计的好处是把两件事拆开了：

Q/K 负责匹配

第 t 个 token 应该看第 j 个 token 多少。

V 负责内容

一旦决定看它，就从它那里拿什么向量内容回来。

如果直接让 q 和 v 同时承担“匹配”和“内容”两个角色，模型的自由度会变小。 Q/K/V 分开后，模型可以学到：

用一种视角判断谁重要；
用另一种视角决定真正传递什么内容。

4. 为什么这种设计能通过训练变好？

因为整条链路都是可微分的。也就是说，从最终 loss 往回，梯度可以一路传到所有参数：

loss ← output ← attention weights ← scores ← Q/K/V ← WQ, WK, WV ← embedding 表

如果某次模型预测错了，loss 会变大。反向传播会告诉模型：

哪些 token 本该多看却没多看

梯度会推动 W_Q 和 W_K，让这些 token 未来更容易得到更高匹配分数。

哪些 token 本不该多看却看太多

梯度会推动 W_Q 和 W_K，让这些错误关注未来降低。

哪些内容应该被传递给后续层

梯度会推动 W_V，让 value 向量携带更有用的内容。

5. 这一段的最终回答

Q/K/V 是人类命名的理解框架；
也是 Transformer 真实的参数化计算结构；
设计者规定了“如何算”，训练决定“算出什么模式”。

追加问答 02 / 2026-05-14

V 决定“被拿走的内容形态”到底是什么意思？

你问得很关键：最终向量不都是表示这个 token 吗？为什么还要说 V 决定“内容形态”？

先把一句话改得更准确： V 不是决定“看谁”，而是决定“被看见的那个 token，要以什么向量形式贡献给别人”。

1. 一个 token 在 attention 里有两个身份

在 self-attention 里，同一个 token 同时有两个角色：

作为正在更新的位置 t

它用自己的 query 去决定应该参考谁。

作为被别人参考的位置 j

它用自己的 value 向量给别人提供内容。

所以要区分两个东西：

outputt：第 t 个位置更新后的向量
vj：第 j 个位置提供给别人汇总的 value 向量

最终 output_t 仍然放在第 t 个位置，所以它是“第 t 个 token 的上下文表示”。 但这个表示不再只来自第 t 个 token 自己，它混入了多个 v_j。

2. “内容形态”不是人类语言内容，而是向量特征形式

这里的“内容”不是一句中文解释，也不是人能直接读懂的词义。 它就是一组浮点数，也就是模型内部的特征。

vj = xjWV

W_V 会把原始 token 向量 x_j 转换成 value 向量 v_j。这个转换可以改变：

哪些特征被放大

某些维度可能变得更强，更容易影响后续输出。

哪些特征被压低

某些对当前任务不重要的维度可以被弱化。

特征如何重新组合

多个原始维度可以线性组合成新的 value 维度。

所以“内容形态”更准确地说是：

这个 token 在被别人汇总时，应该以怎样的特征向量形式出现。

3. 相同的“看谁”，不同的 V，会得到不同 output

下面这个例子可以直接说明：attention 权重不变，也就是“看谁”不变； 但 W_V 不同，拿回来的内容向量不同，最后输出就不同。

假设第 0 个 token 的 attention 权重固定为：
weight = [0.70, 0.30]

也就是说：

第 0 个 token 更新自己时：
70% 参考 token 0
30% 参考 token 1

原始 token 向量设为：

x0 = [1, 0]    x1 = [0, 1]

情况 A：W_V 不改变向量

v0 = [1, 0]    v1 = [0, 1]
output0 = 0.70 · [1, 0] + 0.30 · [0, 1]
output0 = [0.70, 0.30]

情况 B：W_V 改变 value 的特征形式

v0 = [2, 0]    v1 = [0, 0.5]
output0 = 0.70 · [2, 0] + 0.30 · [0, 0.5]
output0 = [1.40, 0.15]
注意： 两种情况的 attention 权重都是 [0.70, 0.30]。 也就是“看谁”的比例完全一样。不同的是 V，所以“拿回来的内容向量”不同。

4. 最终向量是不是还表示这个 token？

是，但要加一个限定：

outputt 表示第 t 个位置的 token，经过上下文融合后的表示。

它仍然属于第 t 个位置。比如第 0 个位置原来是“我”，attention 后的 output_0 仍然是第 0 个位置的表示。 但它已经不是孤立的“我”的 embedding，而是：

“我” + 它参考到的其他 token 信息

所以你可以这样区分：

对象 它表示什么
x_t 第 t 个位置进入 attention 前的 token 表示。
v_j 第 j 个 token 被别人参考时，提供出去的内容向量。
output_t 第 t 个位置汇总多个 v_j 后得到的上下文表示。
V 决定的不是“最终这个 token 是谁”，
而是“其他 token 看它时，能从它那里拿到什么形式的向量内容”。

下一步学习 / Encoder Block

Encoder Block：Attention 之后为什么还要 Residual、LayerNorm 和 FFN？

到这里，你已经大概理解了 attention 如何让每个 token 汇总上下文。接下来要看完整 Encoder Block： attention 只是其中一个子层，后面还要接 residual、LayerNorm 和 FFN（Feed Forward Network，前馈神经网络）。

x → Self-Attention → Residual Add → LayerNorm → FFN → Residual Add → LayerNorm
先抓住一句话： Attention 负责让 token 看上下文；Residual 负责保留原信息和提供稳定路径； LayerNorm 负责稳定每个 token 向量的数值分布；FFN 负责对每个 token 的向量做进一步非线性加工。

1. 先定义符号，避免公式看起来像黑箱

符号 含义 shape
x 进入 Encoder Block 的 token 向量序列 [B, T, D]
B batch size，一次输入几条序列 例如 2
T seq_len，每条序列几个 token 例如 5
D embed_dim，每个 token 向量多少维 例如 16
Attn(x) Self-Attention 输出的上下文向量 [B, T, D]
FFN(y) Feed Forward Network 对每个 token 独立加工后的输出 [B, T, D]

2. Residual Add：为什么要加回原来的 x？

Attention 会生成一个上下文向量 Attn(x)。 但 Transformer 通常不会直接用它替换原来的 x，而是先相加：

y = LayerNorm(x + Attn(x))

这里的加法是逐元素相加。因为：

x.shape = [B, T, D]
Attn(x).shape = [B, T, D]
所以 x + Attn(x) 的 shape 仍然是 [B, T, D]

residual 的直觉是：不要让 attention 子层完全接管 token 表示，而是让它在原表示基础上补充或修正。

没有 residual

输出只来自 attention。如果 attention 暂时学得不好，原始信息可能被破坏。

有 residual

输出包含原始 x，也包含 attention 的上下文补充，训练更稳。

这可以类比 Day 3/Day 4 的训练：模型不是每次都从零开始重建全部信息，而是在已有表示上继续调整。 residual 给信息和梯度都提供了一条更直接的路径。

3. LayerNorm：到底 norm 什么？

LayerNorm 不是对整个 batch 一起归一化，也不是像 BatchNorm2d 那样按通道统计 batch * height * width。 在 Transformer 里，LayerNorm 通常是：

对每一个 token 自己的 D 维向量做归一化

假设某个 token 的向量是：

u = [u1, u2, ..., uD]

LayerNorm 会先计算这个 token 向量内部的平均值：

μ = u1 + u2 + ... + uD D

再计算方差：

σ² = (u1-μ)² + (u2-μ)² + ... + (uD-μ)² D

然后把每一维标准化：

norm(ui) = ui - μ sqrt(σ² + ε)
符号 含义
u_i 当前 token 向量的第 i 个维度
μ 这个 token 向量 D 个维度的平均值
σ² 这个 token 向量 D 个维度的方差
ε 一个很小的数，防止除以 0

LayerNorm 做完标准化后，通常还有两个可学习参数：

output = γ · norm(u) + β

其中 γ 和 β 也是训练出来的参数。它们让模型在稳定数值分布的同时，仍然保留调整表达范围的能力。

和 Day 4 BatchNorm 的区别： BatchNorm2d 主要按通道跨 batch 和空间位置统计；LayerNorm 在 Transformer 里通常对单个 token 的 D 维向量内部统计。

4. FFN：为什么 attention 后还要逐 token 加工？

Attention 主要负责 token 之间交换信息。FFN 主要负责对每个 token 的向量做进一步非线性变换。

FFN(u) = Linear2(Activation(Linear1(u)))

典型结构是：

Linear(D, D_ff) → GELU/ReLU → Linear(D_ff, D)

比如：

D = 16
D_ff = 64
FFN: 16 → 64 → 16

它先扩维，再压回原维度。这样做的直觉是：

先扩展表达空间

把 16 维 token 向量映射到更宽的 64 维空间，允许模型形成更多中间特征。

加入非线性

GELU/ReLU 让模型不是单纯线性变换，否则多层 Linear 合起来仍然接近一个 Linear。

压回 embed_dim

输出回到 D 维，方便和 residual 相加，也方便进入下一个 Encoder Block。

注意： FFN 是逐 token 独立执行的。它不会让 token 之间互相看；token 之间的信息交换主要发生在 Self-Attention。

5. 第二次 Residual + LayerNorm

FFN 输出后，也不会直接替换前面的向量，而是再做一次 residual：

z = LayerNorm(y + FFN(y))

这里：

y.shape = [B, T, D]
FFN(y).shape = [B, T, D]
z.shape = [B, T, D]

所以完整 Encoder Block 输入和输出 shape 一样：

[B, T, D] → Encoder Block → [B, T, D]

6. 一个重要但暂时不展开的事实：Pre-LN 和 Post-LN

很多教材图会写成：

y = LayerNorm(x + Attn(x))
z = LayerNorm(y + FFN(y))

这常被称为 Post-LN，也就是先子层、再相加、再归一化。 但很多现代大模型实现会使用 Pre-LN：

y = x + Attn(LayerNorm(x))
z = y + FFN(LayerNorm(y))

你现在不需要马上纠结两者差异。先掌握共同点：

attention / FFN 子层 + residual path + LayerNorm 稳定数值

7. 当前小结

Self-Attention

让每个 token 汇总其他 token 的信息。

Residual

把原输入加回来，让模型在原表示上补充和修正。

LayerNorm

对每个 token 的 D 维向量内部做归一化，稳定训练。

FFN

对每个 token 独立做非线性加工，增强表达能力。

追加问答 03 / 2026-05-14

FFN 公式逐行拆解：为什么是 Linear → Activation → Linear？

FFN 的全称是 Feed Forward Network，中文常译为前馈神经网络。在 Transformer Encoder 里，更准确地说，它是 position-wise feed-forward network，也就是“对每个位置的 token 向量分别执行同一套前馈网络”。

先纠正缩写： 这里讨论的是 FFN，不是 FNN。 在 Transformer 语境里，FFN 通常指 Feed Forward Network。

1. FFN(u) = Linear2(Activation(Linear1(u))) 里的符号是什么？

FFN(u) = Linear2(Activation(Linear1(u)))
符号 含义 shape 示例
u 某一个 token 当前的向量。它通常已经经过 attention、residual 和 LayerNorm。 [D]
D embed_dim，也就是每个 token 向量的维度。 例如 16
D_ff FFN 中间隐藏层维度，通常比 D 大。 例如 64
Linear1 第一层线性变换，把 token 向量从 D 维扩到 D_ff 维。 D → D_ff
Activation 非线性激活函数，例如 GELU 或 ReLU。 shape 不变
Linear2 第二层线性变换，把 D_ff 维压回 D 维。 D_ff → D

2. 把公式拆成三步

为了看清楚，不要一口气读完整个嵌套公式。把它拆开：

a = Linear1(u)
h = Activation(a)
o = Linear2(h)
FFN(u) = o

其中：

中间变量 含义 shape
u 输入 token 向量 [D]
a 第一层 Linear 后的中间向量 [D_ff]
h 激活函数处理后的中间向量 [D_ff]
o 第二层 Linear 后的输出向量 [D]

3. Linear1 到底怎么算？

假设当前 token 向量是行向量：

u.shape = [D]

第一层 Linear 有参数：

W1.shape = [D, D_ff]
b1.shape = [D_ff]

计算：

a = uW1 + b1

这和 Day 3 里 Linear 层的本质一样：输入向量乘权重矩阵，再加 bias。 只是这里不是直接输出类别 logits，而是在 token 向量内部做特征变换。

4. Activation 为什么必须存在？

如果没有 Activation，那么 FFN 就变成：

FFN(u) = Linear2(Linear1(u))

两个线性变换叠在一起，本质上仍然可以合并成一个更大的线性变换。 这会限制模型表达能力。

Activation 的作用： 引入非线性，让 FFN 可以表达更复杂的特征组合，而不是只做一次线性重排。

常见激活函数：

ReLU

负数变 0，正数保留。你在 Day 3 / Day 4 已经见过。

GELU

Transformer 里更常见，效果更平滑。可以先理解为一种更柔和的 ReLU。

5. 为什么要先扩维再压回去？

典型 FFN 不是：

D → D

而是：

D → D_ff → D

例如：

16 → 64 → 16

先扩到更大的维度，是为了给模型一个更宽的中间空间，让它能临时展开更多特征组合。 再压回 D 维，是为了保持 Encoder Block 的输入输出 shape 一致，方便 residual 相加和堆叠多层。

6. FFN 的目的、作用和意义

补足 attention 的能力

Attention 主要负责 token 之间交换信息；FFN 负责在每个 token 内部继续加工这些信息。

增加非线性表达

没有非线性，模型很难表达复杂模式。Activation 让 token 特征可以发生更复杂变化。

逐 token 做“思考加工”

Self-Attention 先把上下文信息汇入 token；FFN 再对这个融合后的 token 向量做进一步处理。

保持结构可堆叠

FFN 输出回到 D 维，使每个 Encoder Block 输入输出 shape 一致，可以连续堆很多层。

7. FFN 是不是会看其他 token？

不会。FFN 是逐 token 独立执行的。

对第 0 个 token：o0 = FFN(u0)
对第 1 个 token：o1 = FFN(u1)
对第 2 个 token：o2 = FFN(u2)

它们使用同一套 FFN 参数，但每个 token 单独计算。 token 之间的信息交换主要由 Self-Attention 完成。

Attention：token 之间交流
FFN：每个 token 内部加工

最小 Transformer Encoder 应该怎么写？先看实现地图

现在不急着一次性写完整代码。先把最小实现拆成几个模块：Embedding、Multi-Head Self-Attention、FFN、Encoder Block、整体 Encoder。每个模块只负责一件事。

这一步的目标： 你要能看到一个类或函数名，就知道它在 Transformer Encoder 里负责什么，以及输入输出 shape 应该是什么。

1. 最小实现需要哪些模块？

模块名 负责什么 输入 shape 输出 shape
TokenEmbedding 把 token id 查表成 token 向量。 [B, T] [B, T, D]
PositionEmbedding 给每个位置查一个位置向量。 [B, T] [B, T, D]
MultiHeadSelfAttention 让每个 token 汇总其他 token 的 value 信息。 [B, T, D] [B, T, D]
FeedForwardNetwork 对每个 token 独立做非线性加工。 [B, T, D] [B, T, D]
EncoderBlock 组合 Attention、Residual、LayerNorm、FFN。 [B, T, D] [B, T, D]
MiniTransformerEncoder 把 embedding 和一个或多个 EncoderBlock 串起来。 [B, T] [B, T, D]

2. 先固定一组小参数

为了学习，不要一开始用真实大模型参数。先用小尺寸，这样 shape 很容易检查。

B = batch_size = 2
T = seq_len = 5
D = embed_dim = 16
H = num_heads = 4
d = head_dim = D / H = 16 / 4 = 4
符号 全称或含义 当前例子
B batch size，一次输入几条序列 2
T sequence length，每条序列几个 token 5
D embedding dimension，每个 token 向量多少维 16
H number of heads，attention head 数量 4
d head dimension，每个 head 里的 token 向量维度 4

3. 整体 forward 路线

token_ids → token_embedding + position_embedding → EncoderBlock → encoder_output

4. Multi-Head Self-Attention 代码里最容易错的 shape

这部分之后写代码时要特别慢。核心不是“公式会背”，而是每一步 shape 要对。

输入 x.shape = [B, T, D]
qkv = Linear(x)
qkv.shape = [B, T, 3D]

这里的 3D 是因为一次性生成 Q、K、V 三份向量。

qkv reshape:
[B, T, 3D] → [B, T, 3, H, d] → [3, B, H, T, d]

最后拆开：

Q.shape = [B, H, T, d]
K.shape = [B, H, T, d]
V.shape = [B, H, T, d]
这里最重要： Q/K/V 拆成 head 之后，attention 是在每个 head 内部独立计算。 所以 scores 的 shape 是 [B, H, T, T]。

5. scores、weights、context 的代码地图

scores = Q @ KT / sqrt(d)
scores.shape = [B, H, T, T]

最后两个维度 [T, T] 的含义仍然是：

行：谁在看
列：被看的 token
weights = softmax(scores)
weights.shape = [B, H, T, T]
context = weights @ V
context.shape = [B, H, T, d]

然后把 head 合并回去：

[B, H, T, d] → [B, T, H, d] → [B, T, D]

先写纯 shape demo

只用随机 token ids，打印每一步 shape，不训练。

再写 MultiHeadSelfAttention

重点验证 Q/K/V、scores、weights、context、merge heads 的 shape。

再包 EncoderBlock

加入 residual、LayerNorm、FFN，确认输入输出都是 [B, T, D]。

最后写整体 Encoder

把 token embedding、position embedding 和一个 EncoderBlock 串起来。

下一步真正写代码时，只追求一件事：
每一步 shape 都能解释清楚。

追加问答 04 / 2026-05-15

token 是程序自动切的吗？如果切得很怪怎么办？

你问到的是 Transformer 入口处非常关键的一层：tokenizer。模型本身不直接读原始文字，文字要先经过 tokenizer 变成 token id。

先给结论： 不是研究人员手动逐句切 token。通常是研究人员先选择或训练一个 tokenizer， 得到固定的词表和切分规则。之后每一句话都由程序按照这套固定规则自动切分。

1. tokenizer 是什么？

tokenizer 可以理解成：

原始文本 → token 列表 → token id 列表

例如：

"我喜欢深度学习"
→ ["我", "喜欢", "深度", "学习"]
→ [12, 35, 108, 209]

这只是一个理想例子。真实 tokenizer 不一定按人类词语切，也可能切得更细。

2. 是谁决定怎么切？

不是研究人员对每一句话手工切分，而是先确定一套 tokenizer。这个 tokenizer 里通常有两样东西：

词表 vocab

记录模型认识哪些 token，以及每个 token 对应哪个 id。

切分规则

规定一段文本如何被拆成词表里的 token。

训练大模型前，通常会先在大量文本上训练 tokenizer，或者直接选用已有 tokenizer。 一旦 tokenizer 确定，后续模型训练和推理都必须使用同一个 tokenizer。

tokenizer 固定
→ 文本切分方式固定
→ token id 映射固定
→ 模型学习这些 id 对应的 embedding

3. 常见切分方式有哪些？

方式 大概做法 问题
按字切 中文每个字一个 token，例如 “深 度 学 习”。 序列会变长，有些词语整体含义要靠模型后面组合。
按词切 按人类词语切，例如 “深度 学习”。 遇到新词、罕见词、错别字时很麻烦。
子词切分 介于字和词之间，常见片段成为 token，罕见词继续拆小。 切出来的 token 有时不像完整词，但工程上更灵活。

现代 LLM 常用的是子词切分思想，例如 BPE、WordPiece、SentencePiece 一类方法。 你现在不用急着掌握算法细节，先知道它们的目标：

常见片段尽量合成较大 token；
罕见片段可以继续拆小，保证几乎任何文本都能表示。

4. 如果切成“我喜 / 欢 / 深度 / 学 / 习”怎么办？

这种情况在理论上是可以发生的，尤其是 tokenizer 词表和规则不理想时。 但只要每个片段都在词表里，它仍然可以被模型处理：

["我喜", "欢", "深度", "学", "习"]
→ [id_a, id_b, id_c, id_d, id_e]
→ embedding 向量序列
→ Transformer 继续处理

也就是说，模型不会因为 token 不是人类眼里的完整词就完全不能工作。 Transformer 后面的 self-attention 可以把多个 token 的信息重新组合起来。

但是： 切得太怪会让学习更困难、更低效。因为模型要花更多层、更多 attention 去重新组合这些被切碎的片段。

5. 切得怪会带来什么影响？

序列变长

“深度学习”如果是 1 个 token，只占 1 个位置；如果拆成 4 个字，就占 4 个位置。

上下文窗口被浪费

同样长度的文本会占更多 token，能放进模型上下文的内容变少。

语义组合压力变大

模型需要自己学会把“学”和“习”组合成“学习”的含义。

罕见切分可能学得差

如果某个奇怪 token 在训练数据里很少出现，它的 embedding 可能学得不充分。

6. 那 tokenizer 是不是越按人类词语切越好？

不一定。完全按词切会遇到一个严重问题：世界上新词、专有名词、拼写变体、代码片段、表情、错别字太多。 如果词表没有某个词，模型就不知道怎么表示。

子词 tokenizer 的好处是：

常见词可以成为整体 token；
不常见词可以拆成更小片段；
新词也能被表示出来。

所以它是在这两件事之间折中：

切太细

表示能力稳定，但序列很长，效率低。

切太粗

常见词效率高，但新词和罕见词难处理。

7. 和 embedding 的关系

tokenizer 决定 token id。embedding 表根据 token id 查向量。

tokenizer 负责：文本 → token id
embedding 负责：token id → 向量

所以，如果 tokenizer 把一句话切成 5 个 token，那么模型输入就是 5 个 token id； 后面的 seq_len 就是 5。

seq_len = 当前输入序列中的 token 数量

8. 当前结论

token 不是研究人员逐句手切的；
tokenizer 用固定词表和规则自动切；
切得不符合人类词语也能训练，但可能更低效；
Transformer 会在后续层里重新组合这些 token 的信息。

追加问答 05 / 2026-05-15

qkv_packed、reshape、permute 到底在整理什么？

你现在卡住的不是 attention 公式，而是张量维度整理。这里不要把它想成新数学， 它更像是在把一堆已经算好的数字重新装箱、换标签、换摆放顺序。

先给一句话版： qkv_projection 先给每个 token 算出一整条 [Q, K, V] 混在一起的长向量； view 把这条长向量拆成“Q/K/V、head、head_dim”； permute 把维度顺序换成后面 attention 更方便计算的格式。

1. 先看当前 demo 的固定数字

B = 2   batch 里有 2 条序列
T = 5   每条序列有 5 个 token
D = 4   每个 token 向量是 4 维
H = 2   有 2 个 attention head
d = 2   每个 head 里向量是 2 维

因为：

D = H × d = 2 × 2 = 4

所以一个 token 的 Q 是 4 个数，可以拆成 2 个 head，每个 head 2 个数。 K 和 V 也是一样。

2. qkv_projection = Linear(D, 3D) 是一次性生成 Q/K/V

qkv_projection = nn.Linear(in_features=D, out_features=3D)

当前 demo 中：

D = 4
3D = 12
qkv_projection = nn.Linear(4, 12)

它的意思不是“12 个 token”或“12 个 head”，而是：

每个 token 原本 4 维；
经过这个 Linear 后变成 12 维；
这 12 维里面装着 Q、K、V 三份 4 维向量。
区间 含义 当前长度
0 : D Q 向量 4 个数
D : 2D K 向量 4 个数
2D : 3D V 向量 4 个数

3. weight.shape = (12, 4) 为什么不是 (4, 12)？

PyTorch 的 nn.Linear(in_features, out_features) 把 weight 存成：

weight.shape = [out_features, in_features]

所以：

nn.Linear(4, 12)
weight.shape = [12, 4]
bias.shape = [12]

它可以理解成：

12 个输出维度；
每个输出维度都由输入的 4 个维度算出来。

实际计算时等价于：

output = input @ weight.T + bias

所以：

input.shape = [B, T, 4]
weight.T.shape = [4, 12]
output.shape = [B, T, 12]
注意： PyTorch 这样存，不代表输入是 12 维、输出是 4 维。 nn.Linear(4, 12) 的语义永远是 4 维输入、12 维输出。

4. qkv_packed 是什么？

qkv_packed = qkv_projection(encoder_input)

当前：

encoder_input.shape = [2, 5, 4]
qkv_packed.shape = [2, 5, 12]

这表示：

2 条序列；
每条 5 个 token；
每个 token 现在有 12 个数，里面塞着 Q、K、V。

例如一个 token 的 12 个数可以看成：

qkv_packed[b, t] = [q0, q1, q2, q3,   k0, k1, k2, k3,   v0, v1, v2, v3]

5. qkv_reshaped = view(B, T, 3, H, d) 是把长条拆成盒子

qkv_reshaped = qkv_packed.view(B, T, 3, H, d)

当前数字代入：

[B, T, 12]
→ [B, T, 3, H, d]
→ [2, 5, 3, 2, 2]

这个操作没有重新计算 Q/K/V，只是重新解释同一批数字的摆放方式。

[12]
→ [3, 2, 2]

对一个 token 来说：

3：Q / K / V 三组
2：两个 head
2：每个 head 里面两个数

6. permute(2, 0, 3, 1, 4) 是换维度顺序，不是改数字

qkv_for_attention = qkv_reshaped.permute(2, 0, 3, 1, 4)

先给 qkv_reshaped 的每个维度贴标签：

原维度编号 标签 含义 当前大小
0 B batch 中第几条序列 2
1 T 第几个 token 位置 5
2 QKV 第 0 组是 Q，第 1 组是 K，第 2 组是 V 3
3 H 第几个 attention head 2
4 d 每个 head 里面的向量维度 2

原来的顺序是：

qkv_reshaped.shape = [B, T, QKV, H, d]
也就是维度编号 [0, 1, 2, 3, 4]

permute(2, 0, 3, 1, 4) 的意思是：

新第 0 维 = 旧第 2 维 = QKV
新第 1 维 = 旧第 0 维 = B
新第 2 维 = 旧第 3 维 = H
新第 3 维 = 旧第 1 维 = T
新第 4 维 = 旧第 4 维 = d

所以 shape 从：

[B, T, QKV, H, d] → [QKV, B, H, T, d]

当前数字就是：

[2, 5, 3, 2, 2] → [3, 2, 2, 5, 2]

7. 为什么要把 QKV 放到最前面？

因为这样后面可以很方便地拆出：

query, key, value = qkv_for_attention.unbind(dim=0)

由于第 0 维现在是 QKV，所以：

qkv_for_attention[0] = 所有 Q
qkv_for_attention[1] = 所有 K
qkv_for_attention[2] = 所有 V

拆出来以后：

query.shape = key.shape = value.shape = [B, H, T, d]

当前就是：

[2, 2, 5, 2]

8. 为什么要把 H 放到 T 前面？

因为 attention 是在每个 batch、每个 head 内部单独算的。 我们希望每个 head 看到的是：

Q[b, h].shape = [T, d]
K[b, h].shape = [T, d]
V[b, h].shape = [T, d]

这样下一步就能直接算：

scores[b, h] = Q[b, h] @ K[b, h].T

shape 是：

[T, d] @ [d, T] = [T, T]

所有 batch 和 head 一起算时：

scores.shape = [B, H, T, T]
所以 permute 的目的不是改变含义， 而是把张量整理成后续矩阵乘法最顺手的形状： 每个 batch、每个 head 都有一张 [T, T] 的 attention 分数表。

9. 这段代码的形象理解

Linear：给每个 token 打包三份材料

每个 token 从 D 维变成 3D 维，里面顺序放着 Q、K、V。

view：把一条长材料拆成分格盒子

从 [12] 拆成 [3, 2, 2]，也就是 Q/K/V、head、head_dim。

permute：把盒子的维度顺序重新摆放

从 [B,T,QKV,H,d] 改成 [QKV,B,H,T,d]，方便先拿出 Q/K/V。

unbind：把 Q、K、V 三摞材料分开

最后得到 query/key/value，每个都是 [B,H,T,d]。

这一整段没有训练，也没有 attention 计算；
它只是在准备 Q/K/V 的形状。

6. 当前你应该拿稳的结论

Embedding

token id 查 token embedding 表，position id 查 position embedding 表。

Q/K/V

它们都是向量。Q/K 决定权重，V 决定被汇总的内容。

Attention 输出

attention 是 forward 中的新上下文向量，不是直接修改参数。

Multi-Head

先投影，再拆 head。多个 head 各自算关系，最后合并。

token embedding：这个 token 是谁
position embedding：这个 token 在哪里
attention：这个 token 应该参考谁，并汇总什么内容
