DAY 08 · VISUAL TOKENIZATION

ViT Patch Embedding

图片像素怎样变成 Transformer 可以处理的 token 序列？

切分 patch、展平并线性投影，使二维图片成为一串带位置信息的视觉 embedding。

它是后续 CLIP vision encoder 和 VLM image tokens 的底层入口。

打开 Day8 教学文档

输入

image tensor [B, C, H, W]

输出

patch embeddings [B, N, D]

系统职责

把视觉空间转换为 token 空间

2.2 每层能力都对应一个失败边界

层级解决的问题典型失败设计时要问什么
视觉 token 化把图片转换为序列表示分辨率不足，小字或细节丢失输入尺寸是否适合 OCR 与图表？
视觉语义表示识别物体、场景和语义关系细粒度属性、空间关系不稳定视觉塔是否覆盖目标任务？
跨模态对齐让视觉信息进入语言空间图片信息被压缩或映射不足模型是否针对图文任务训练？
语言生成按问题组织自然语言回答遗漏要点、幻觉、回答不完整提示词和输出契约如何约束？
产品系统处理输入、运行、记录与失败格式错误、资源不足、结果不可追踪如何校验、降级、记录和评测？

3. Step 02：定义通用多模态 Demo

你的目标已经明确：它是一个用于学习和验证 VLM 能力的通用小助手 Demo。第一版重点是跑通稳定的数据流、观察能力边界，而不是一次性覆盖所有模态和生产场景。

当前需求基线：单张图片与文本问题共同输入，模型生成自然语言回答；覆盖软件截图、基础图表和普通照片三类常见视觉任务。

3.1 “通用多模态”需要先收窄

第一版支持暂不支持原因
单张图片 + 文本问题多图对比、视频、音频先把最小多模态链路做稳定，避免输入组织和模型选型同时膨胀。
截图、图表、普通照片医疗、遥感、工业质检等专业领域通用模型可以做基础理解，但不应把专业可靠性作为 Demo 承诺。
自然语言回答自动操作界面、执行外部动作当前目标是理解与问答，不引入工具调用和外部副作用。
本地单用户运行高并发、权限、计费、SLA这些属于产品化与服务治理，不是当前学习主线。
概念纠偏：“支持多模态”在第一版中具体指图片模态和文本模态共同参与一次推理，不等于同时支持图片、视频、音频、文档和任意工具。

3.2 三类通用任务的契约不同

TASK 01 · SCREENSHOT

软件截图理解

识别界面中的文字、控件、状态和相对位置，并围绕用户指定的问题回答。

示例：当前页面显示了什么错误？哪个按钮可以继续执行？

重点能力

OCR + 控件语义 + 布局关系

主要风险

小字漏读、状态区域混淆、控件关系判断错误

验收方式

答案覆盖指定文字、控件和状态要点

3.3 输入、输出和失败契约

输入

  • 必选：一个有效图片路径
  • 必选：一个文本问题
  • 可选：任务模式与生成参数

输出

  • 自然语言回答
  • 模型、设备和耗时
  • 可选的结构化 JSONL 记录

失败

  • 图片不存在或格式不支持
  • 资源不足或模型加载失败
  • 视觉信息不足时明确说明
request = {
  "image": "path/to/image.png",
  "question": "这张图片中最重要的信息是什么？",
  "task_mode": "auto"
}

response = {
  "answer": "...",
  "model": "...",
  "device": "...",
  "latency_ms": 0,
  "error": null
}

task_mode 默认使用 auto，让通用问答保持简单；评测时可以显式指定 screenshot、chart 或 photo，便于采用不同提示词和评分规则。

不承诺“什么都能答”：通用 Demo 的价值是让三类代表性任务走过同一条 VLM 推理链路，并真实记录成功与失败，而不是隐藏模型能力边界。
